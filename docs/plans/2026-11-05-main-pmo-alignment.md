# Main 与 PMO 目标对齐：现状判定、拆行重述与 8 周执行计划

日期：2026-11-05
对象：Main 专家（PMO G3·S6，#43 全栈开发 Agent 与飞书机器人、#44 模型选型与评测平台）
载体：`main.luteos.com`（当前为 ANB 方法站）、`llm.luteos.com`（当前为静态模型目录）
依据：pmo.luteos.com 首页 / `/projects` / `/roadmap` / `/sop` / `/sites`（抓取日 2026-11-05）；`reports/Main-项目成果总结-20261105.md`（实跑）
性质：评审用执行方案。三项方向已拍板：拆行重述、模板优先、站点归位。

## 一、结论

1. PMO 记录 Main 为 **100% / Stage 4 标杆**。按 PMO 自己的四阶门禁复核，Main 实际是
   **Main-Base 100% + Main-Agent 50% + Main-Eval 约 35%**。
2. 差距不在代码量，在**真实使用**与**卡片闭环**：无 `card.action.trigger` 入站处理，
   无高频问题埋点，真实群 252 条消息只有 1 个唯一问题、0 条可见答案。
3. 不建议下调整行分数，建议**拆行**：真的部分保住 100%，假的部分给出可验收的追赶路径；
   并把 Main 的 Stage 2 收口直接做成 Wave 2/3 十三个 Bot 的模板。

## 五、根因

1. **验收载体错配**：PMO 把 `main.luteos.com` 当作 Main 工作台，实际它是 ANB 方法站。载体不证明能力，分数就悬空。
2. **阶段门禁未埋点**：没有卡片动作入站、没有高频问题统计。即使 Stage 3 真的发生，也拿不出证据。
3. **度量口径错配**：PMO 顶层运营模型要 `measuredActions`，Main 只有测试数和站点在线。测试通过不是采纳。
4. **阻塞项**：写入路径损坏未定位。`layout.tsx` 修复后再次损坏，typecheck 直接红。在根因解决前，任何“已完成”都可能被下一次编辑推翻。

## 八、工作流与票据

### WS1 工程止血（周健，W1）

- M-01 写路径根因定位。timebox 2 天；到期未定位，转为“带门禁继续”，禁止无门禁写入。
- M-02 本地字节门禁。新增 `scripts/check-padded.mjs`：Node 读 `st_size`、Python 读真实字节，
  差值 4096 即红；`--fix` 原子重写。Git 索引只存干净 blob（实测 1131B），CI 检出看不到尾巴，
  所以门禁必须跑在工作树/提交前，不能只放 CI。
- M-03 工作树分批入库。按主题分 4~6 批：读取层防线、站点重构、架构图、ANB 资产、报告。
  每批入库前跑 typecheck + 单测 + 字节门禁。

### WS2 网关模板（周健 + 刘华丽，W2–W3）

- M-04 卡片动作入站。处理 `card.action.trigger`，把按钮动作映射为任务/状态变更并落 SQLite；
  幂等键沿用 `event_id` 约定。
- M-05 事件埋点。每条入站事件记录：问题指纹、提问人、意图、是否命中知识、是否被采纳。
  这是 Stage 3 的唯一证据源。
- M-06 模板 v1.1 文档 + 接入。文档说明“复制哪几个文件、配哪几个环境变量、跑哪几个测试”；
  Clone 与 Vicky 作为首批接入，要求 0 fork。
- M-07 Recipe Ticket 04。`RecipeRunner` 接 `packages/core` 的 `run()`，再做真实群 E2E。
- M-08 @Main 真人 10 问验收。问题来自真实群，不接受自写题；记录每问的回答与人工判定。

### WS3 Agent 质量与自进化（刘华丽，W2–W7）

- M-09 rubric judge 凭据配置，重跑 Recipe 14 案例与 Main 150 案例，rubric 维度不再 skipped。
- M-10 高频统计与 SOP 蒸馏。按 ≥10 次/周或打回 ≥3 次筛选；每条 SOP 过三道门禁，
  返工率 <20% 才允许固化。
- M-11 Stage 4 固化。把稳定 2 周的 SOP 迁入工作台自动化工位，保留回滚开关。

### WS4 工作台与站点（吴雨宁，W6）

- M-12 `main.luteos.com/workbench`：eval 结果、Bot 健康、Token 成本、SOP 工位四个视图。
- M-13 ANB 迁 `/anb`，保留旧链接 301；`deploy/accept.sh` 增加新路径验收。

### WS5 PMO 口径（周健，W3 + W8）

- M-14 PMO Main 行拆为三行，附本计划链接与证据链接。
- M-15 `measuredActions` 回写。Main 每周上报：模板复用数、门禁拦截数、Token 成本、
  真实问答采纳数。

## 九、验收与停止信号

**Stage 2 通过**：按钮点击产生任务行；10 个真实问题中 ≥8 被人工接受；真实群卡片可见。

**Stage 3 通过**：连续 2 周 ≥10 问/周；≥3 条 SOP 过三道门禁；返工率 <20%。

**Stage 4 通过**：连续 14 天自动产出；3 条 SOP 在工作台可点击运行；有回滚记录。

**停止信号**（出现即停，不许把没发生的事写成已发生）：

- 11-08 结束 typecheck 仍红 → 冻结功能开发，全员转向写路径。
- 连续 2 周 <10 问/周 → Stage 3 判为未达成，如实报 Stage 2，不用自写题凑数。
- 第二个 Bot 接入需要 fork → 模板未 ready，先修模板，不推广。

## 十、风险与对策

| 风险 | 概率 | 影响 | 对策 |
| --- | --- | --- | --- |
| 写路径根因已定位，上游未修 | 高 | 每次 Write/Edit 可能再污染 | 本地 pre-commit 门禁；`--fix` 归一化；避免用 Write/Edit 写仓库文件 |
