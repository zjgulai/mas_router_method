运营 1 张表

看得出它有没有被用、有没有变好

这一页是表的样张，不是方法论。方法在运营那一页。两页读的是同一件事：一页讲这一步要问什么，一页讲答案记在哪一列。

07 运营

看什么信号，多久没动静算异常。

ops-01 每天各源的成功率、三种失败计数（抓到了/抓错了/无法判断）ops-02 库的增长速率、存储成本、重复率ops-03 按周计算的准确率漂移、置信度分布ops-04 每日计算的完成情况、分母规模ops-05 每周重估的收敛性、系数稳定性ops-06 访问日志：有没有人看、看到多深ops-07 被使用次数、被反驳次数、被推翻次数ops-08 发送记录、回应、以及有没有人因为某条报告改了做法

8 条记录、13 个字段。每个字段下是这个值现在填的是什么；空着的字段也列出来，因为「没填」和「不需要填」在表里长得一样，在这里必须能分开看。

ops-01

运营编号ops-01
多久没动静算异常连续 26 小时没有 run 记录
产品数说
哪一层采集
备注三种失败必须分开计数。合并成一个「失败」会让「没抓到」和「抓到了但解析不了」看起来一样，而前者要重跑、后者要改 adapter。
多久看一次每天 09:00 自动
异常的信号长什么样某源连续两天成功率 0，且没有告警；或者 empty 突然变成 100%
正常的信号长什么样五个源成功率都 > 95%，empty 是 0 或接近 0
状态还没跑过
现在的值—
看的是什么每天各源的成功率、三种失败计数（抓到了/抓错了/无法判断）
这个信号会自己过期吗不会
通知方式飞书群 + 告警卡片
