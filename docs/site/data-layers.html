8+3 层级契约与检查器

数据产品的八个工序层（采集、存储、打标、指标、分析、呈现、结论、报告）与三个横切义务柱（口径、质量、血缘）。每一层要么有一个可执行的命令级检查器，要么它只是一句愿望。

三条不变量铁律：
1. first_seen_at 不是可被修改的列，而是读侧计算的 min()，历史不可改写。
2. 空抓必须留存显式日志记录，明确区分「数据为空」与「抓取失败」。
3. 数据迁移是读侧的（追加 migration 规则），旧数据永远保持原样可查。

一、链 A：采集与存储的基础契约

层级输入契约输出契约失败模式检查命令
采集层 (Collection)Apify actor / 第三方 API 原始返回{raw, first_seen_at, fetched_at, source_task_id, schema_version, taxonomy_version, metric_version}时滞跨区域不一致；抓取时点缺失；空抓不记录collect-audit (0=通过 / 1=失败 / 2=无法判断)
存储层 (Storage)采集层适配器输出的标准观察记录按条目单行归档：first_seen_at 为最早一次，raw 为最新一次，保留所有历史原始快照first_seen_at 被重跑覆盖；字段迁移后旧版本数据无法读取collect-store verify (0=不变量成立 / 1=有结构性破坏)

三、横切三柱的每层义务

口径 (Definition)

每个数字的公式、时间窗、分子分母、异常值处理必须单一来源定义，修改必须升版本号。

质量 (Quality)

必须能够区分真实 0、抓取失败、未到抓取周期三态，不允许静默填补假数据。

血缘 (Lineage)

任意一个报表上的数字，必须能够无歧义地回溯到对应的原始数据快照与处理代码版本。
