01需求

把「我想做个 X」变成一句话：谁在什么情况下用、用完他能做什么以前做不到的事。

方法论已覆盖　这一步由 anb-idea 覆盖，完整。

为什么这一步重要：这一步决定后面所有事。写错方向，后面每一步都在加固一个错误假设，而且越往后返工越贵。

什么情况走哪条路

按代价排序，不按发生概率。先做便宜且能推翻结论的。点击跳到对应处理。

如果去为什么
你说的是功能清单（"要有登录、能导出"）功能清单不是问题功能是解决方案，不是问题。跳过它会让你在验收时无从判断好坏。
你说的是品类（"用 AI 做内容"）品类不是用途品类不是用途。问：谁、在哪一天、用它做什么。
你已经有一句话，但说不清"什么情况说明不该做"缺一个可证伪的否定条件缺这一句，你后面无法判断自己是不是错了。
你说得清用途和对象，但说不清"它给你什么"说得清用途，说不清产出第五句问的是他能做什么，不是这东西还给他什么。这两个不一样，而第二个没人会主动写。
你的否定条件写着"做不出来就别做"，而你说"但人能判断出来"「人能判断出来」不等于「产品能判断」"人能判断"不等于"产品能判断"。这两个一个听起来像另一个，而它们决定产品存不存在。
你有清晰的一句话，且否定条件可测这一步过了进入设计。

功能清单不是问题

「要有登录」是解决方案。要问的是：登录是为了让谁做什么？如果答案是"让每一个用户只能看到自己的数据"，那么真正的问题是隔离，而隔离可以用别的方式解决。

怎么改：每个功能后面追问一句"它让用户能做什么以前做不到的事"。答不上来的功能，先不做。

品类不是用途

「用 AI 做内容」等于没说。它可以是任何人做任何事。

怎么改：问三个具体问题——谁、在什么情况下、他今天没有更好的办法是因为什么。第三个问题是关键，它决定了这个产品有没有存在理由。

缺一个可证伪的否定条件

「如果没人用」不是否定条件，那是任何产品都成立的废话。

怎么改：写一个可以被测量的事件。例："如果五个指标拼出来的结论，和资深从业者凭经验判断的不一致超过三成，那这些指标不承载判断。"这句话在产品做出来之后能被验证。

说得清用途，说不清产出

六句里最容易漏的一句：「它给你什么」。

第四句问的是「他能做什么以前做不到的事」——那是能力；而「打开之后我拿到手的是什么」是产物，两个不同的槽位。

这不是吹毛求疵。实测过：让一个 agent 扮演陌生人、只看这一页，它准确复述出了用途和对象（exit test 按字面是通过的），然后说——「不知道打开之后它给我的是什么」。

怎么改：写成一个能用手的名词。「一份每句都标了依据哪条政策的回复草稿」，不是「更好的回答」。

「人能判断出来」不等于「产品能判断」

否定条件最容易在这里失效。

实测里第二轮的信号是「如果归因做不了，就别做」。问到实际数据，第一反应是——「平台数据里没有，但运营判断得出来」。

那句话听起来像安慰。它不是：运营靠的是经验，而产品继承不了经验，经验也写不成规则。信号已经触发，是那个回答把它盖住了。

怎么查：问「他凭哪一条信息判断」。
· 指向另一个系统（仓库记录、承运商网站、往来邮件）→ 信号没触发，第一步是换输入
· 指向一次要去问人的沟通 → 产品只能做一半，说清是哪一半
· 指向经验（「看多了就知道」）→ 停机

这一步过了

进入下一步。如果这是一个大产品，建议在这里停下来，把这一步的产出写成文件——因为三个月后你会需要它。

谁来验，怎么验

每一行都是一个你能亲手做的动作。做不了就记成未通过，写明缺什么，不要用近似动作代替。

动作通过标准
把六句念给一个不做这行的人，他能复述出用途、对象、以及它会还给他什么他能说出"所以你是在帮谁解决什么"，以及"所以你拿到手的是什么"
你的否定条件是一个可以被测量的事件不是"如果没人用"，而是"如果 X 和 Y 不一致超过三成"
否定条件里说的是"产品能做到",不是"人能做到"问一句：这个判断凭哪一条信息？说得出具体来源，条件没触发；只能答"经验"，条件已经触发了
写下了"这一步需要谁参与"如果需要别人而你找不到，现在就记成未通过

这一步用到哪些 skill

  • interview-me — 把一句话想法问成可验收的意图。需求阶段的内核。
  • anb-idea — 五句话写成想法，含可证伪的否定条件。
  • grilling — 攻击已有草稿，把含糊处问空。
  • grill-me — 七行壳，转调 grilling。
  • grill-with-docs — 拷问同时沉淀术语表与 ADR。
  • wayfinder — 目标大到一个会话装不下时，先画决策地图。
  • agent-delivery-router — 先定车道：incident/exploration/capability/fast。
