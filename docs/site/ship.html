05交付

别人拿到一个地址就能用，不需要你在旁边。

方法论已覆盖　这一步由 anb-shipable 覆盖，但它有一个必须人工完成的验收动作：换一台设备、让另一个人试。

为什么这一步重要：这是你第一次从使用者的位置看它。前面每一步你都在里面，所有东西都是配好的。

什么情况走哪条路

按代价排序，不按发生概率。先做便宜且能推翻结论的。点击跳到对应处理。

如果去为什么
只有你能打开（本地地址）只有你能打开不是交付。密钥、数据、权限、域名四件事在你这里全配好了。
别人能打开，但第一分钟就撞墙别人一进来就撞墙最常见的：配额耗尽、权限不足、依赖缺失。
能打开，也能用，但没人告诉你哪不好没人告诉你哪不好让一个人试，你只看不帮。他卡住的第一步就是下一步的工作。
换一台设备打开过，另一个人用过这一步过了进入运营。

只有你能打开

本机地址、localhost、只在你的机器上有效。

这不是交付。有四件事在你这里是配好的，在别人那里全是缺的：密钥、数据、权限、地址。它们不会在开发时报错，因为开发时它们本来就没被用到。

别人一进来就撞墙

最常见的四种：API 配额耗尽、权限不足、依赖没装、域名/证书问题。

怎么提前发现：算一遍配额。如果一次使用消耗 N 次配额，而你只有 M 次，那第 M/N 个用户就会撞墙。这个算术在写完代码时就能做。

没人告诉你哪不好

你需要一个人，在旁边看着他用，不说话。

看三件事：他第一次点哪里、第一次停顿超过三秒在哪、他问了你什么。每一个问题都是一个缺陷，不是文档缺口。

这一步过了

进入下一步。如果这是一个大产品，建议在这里停下来，把这一步的产出写成文件，因为三个月后你会需要它。

谁来验，怎么验

每一行都是一个你能亲手做的动作。做不了就记成未通过，写明缺什么，不要用近似动作代替。

动作通过标准
用手机打开这个地址打得开才算交付
另一个人在没有解释的情况下用了一次他问的每一个问题都是一个缺陷，不是文档缺口
所有密钥来自环境，不在任何文件里全仓搜一次

实战避坑守则 (Battle Tips)

归属于交付阶段的实战守则摘要。完整复制口令见 作战手卡全表。

守则与手卡入口典型痛点验收判定
01-03 长任务要可观察、可接管多个 Agent 并行跑，最怕失忆、卡住、上下文膨胀和没人知道当前状态。任何分支都能从最近一次产物恢复，不依赖完整聊天记录。
02-06 汇报要能让非工程师判断完成度一堆 commit hash 和工程术语，无法回答到底完成成了什么。读者不打开代码，也能判断范围、原因、证据、验证和待确认项。
05-05 SEO / 从真实站点证据开始套模板写 SEO 报告，容易忽略 robots、跳转、死链和 JS 内容。报告必须能定位到页面和规则，不能只写“优化内容”。

这一步的实战用法

来自实战项目的做法，按它和本阶段的关系收录。完整案例、方法和提示词见 实战用法。

项目一句话来源
Universal Fable 5：把系统提示词删到只剩行为把平台细节删到只剩行为原则，按 core、balanced、complete 三档控制预算。KinetiNode/claude-fable-5-system-prompt-clean
Fable 5 中文版：一套可以直接改的系统提示词骨架不是英文原文的逐字翻译，而是一套能按段替换策略的中文骨架。moely-ai/claude-fable-5-prompt
The Fable Method：把判断问题转成证据问题的 7 步循环分类、定义完成、取证、决策、最小改动、观察验证、结论先行；每一步都有硬边界。Sahir619/fable-method
Fable Mode：把编排做成结构，而不是提示词里的请求stage map、命名委派、可失败的检查、冷验证；orchestrator 没有写权限，worker 才有。mrtooher/fable-mode
fablize：只搬运被实验证明可搬运的程序不提升模型天花板，只让模型走到自己的天花板；只发布验证过效果的程序。fivetaku/fablize
Fable Advisor：架构师不下场打字，按能力分 lane 路由会话当架构师，GPT-6 lane 打字，Fable 在承诺边界和终局做审查。DannyMac180/fable-advisor
Fusion-Fable：独立 panel 加固定 judge，把多个模型合成一个答案同一 prompt 盲跑多个模型，Opus 固定做 judge，输出共识、矛盾、遗漏、盲点。duolahypercho/fusion-fable
Fable Foreman：路由卡是单一事实源，贵的模型要二次批准先证明能用，再按成本/能力选座；lead 亲自验收，贵模型要用户两次确认。olsenbrands/fable-foreman
System Prompts Leaks：把系统提示词当成可对照的工程材料18 个厂商、约 1900 份提示词，按产品和版本归档，能看到行为契约的结构和演变。asgeirtj/system_prompts_leaks
claude-directory：用 prompt、成品和录屏证明一个案例真的能跑541 个项目，每个都带 prompt.md、可运行代码、demo.mp4 和 poster.jpg。pulkitxm/claude-directory

这一步用到哪些 skill

  • anb-shipable：别人能打开、能用，不需要你在旁边。
  • anb-check-otherdevice：换一台设备打开，让另一个人试。
  • pr：PR 正文：最小视图、前后证据、合并风险。
  • deploy-checklist：发布前清单与回滚触发条件。
  • deployment-patterns：滚动/蓝绿/金丝雀、容器化、CI/CD。
  • milestone-report：一页 HTML 里程碑报告，结论先行。
  • make-pr-easy-to-review：整理提交历史、改 PR 正文、给评审指路，不动行为。
  • babysit：盯住一个开着的 PR：修 CI、处理直白的评审意见，推到可合并。
  • blast-radius：上线前找"diff 之外会被这次改动弄坏的东西"，并真跑代码证明唯一侥幸成立的前提。
