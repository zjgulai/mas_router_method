05交付

别人拿到一个地址就能用，不需要你在旁边。

方法论已覆盖　这一步由 anb-shipable 覆盖，但它有一个我做不到的验收动作：换一台设备、让另一个人试。

为什么这一步重要：这是你第一次从使用者的位置看它。前面每一步你都在里面，所有东西都是配好的。

什么情况走哪条路

按代价排序，不按发生概率。先做便宜且能推翻结论的。点击跳到对应处理。

如果去为什么
只有你能打开（本地地址）b-local不是交付。密钥、数据、权限、域名四件事在你这里全配好了。
别人能打开，但第一分钟就撞墙b-wall最常见的：配额耗尽、权限不足、依赖缺失。
能打开，也能用，但没人告诉你哪不好b-nobody让一个人试，你只看不帮。他卡住的第一步就是下一步的工作。
换一台设备打开过，另一个人用过b-next进入运营。

只有你能打开

本机地址、localhost、只在你的机器上有效。

这不是交付。有四件事在你这里是配好的，在别人那里全是缺的：密钥、数据、权限、地址。它们不会在开发时报错，因为开发时它们本来就没被用到。

别人一进来就撞墙

最常见的四种：API 配额耗尽、权限不足、依赖没装、域名/证书问题。

怎么提前发现：算一遍配额。如果一次使用消耗 N 次配额，而你只有 M 次，那第 M/N 个用户就会撞墙。这个算术在写完代码时就能做。

没人告诉你哪不好

你需要一个人，在旁边看着他用，不说话。

看三件事：他第一次点哪里、第一次停顿超过三秒在哪、他问了你什么。每一个问题都是一个缺陷，不是文档缺口。

这一步过了

进入下一步。如果这是一个大产品，建议在这里停下来，把这一步的产出写成文件——因为三个月后你会需要它。

谁来验，怎么验

每一行都是一个你能亲手做的动作。做不了就记成未通过，写明缺什么，不要用近似动作代替。

动作通过标准
用手机打开这个地址打得开才算交付
另一个人在没有解释的情况下用了一次他问的每一个问题都是一个缺陷，不是文档缺口
所有密钥来自环境，不在任何文件里全仓搜一次

这一步用到哪些 skill

  • anb-shipable — 别人能打开、能用，不需要你在旁边。
  • anb-check-otherdevice — 换一台设备打开，让另一个人试。
  • pr — PR 正文：最小视图、前后证据、合并风险。
  • deploy-checklist — 发布前清单与回滚触发条件。
  • deployment-patterns — 滚动/蓝绿/金丝雀、容器化、CI/CD。
  • milestone-report — 一页 HTML 里程碑报告，结论先行。
