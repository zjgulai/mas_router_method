总览 / Agent 工具链

Agent 全栈工具链

三件本地工具，各管一段：Lody 管多机多 Agent 调度，Magpie 管模型路由与降本，Nowledge Mem 管跨会话记忆。它们互不依赖——但按下面的方式接起来，一条链就通了：记忆注水 → 调度派活 → 路由降本 → 验收回流 → 记忆沉淀。

三个工具各管什么

选型的第一问不是"它有什么功能"，而是"它不做什么"。三件事必须分开：模型从哪来（Magpie）、活怎么派（Lody）、昨天学到的怎么带到今天（Nowledge Mem）。

工具一句话定位管什么不管什么
Magpie本地模型路由网关所有 Agent 的请求统一走 127.0.0.1:3425；OpenAI/Anthropic/Gemini 协议互转；路由组容灾（429 自动切换）；订阅桥接降本；本地用量账本不编排 Agent、不存记忆、不管部署
Lody多机多 Agent 控制平面把多台机器池化成一个执行池；Git worktree 隔离并行会话；ACP 协议托管 40+ Agent CLI；长任务异步回执；Diff 评审与行级批注不写 Spec、不管知识库、不做 Eval 判题、不托管生产 Bot
Nowledge Mem跨会话 Agent 记忆会话启动注入工作记忆简报；持久记忆带 8 种类型与检索；Space 物理隔离项目；对话蒸馏沉淀；规则与技能托管不做实时协作、不当向量数据库卖、不替你做架构决策

Lody：多机调度

本地优先的多机 Agent 控制平面。你的笔记本是控制端，重活派给局域网里的服务器跑。 仓库：https://github.com/LodyAI/Lody。

优先级板块在 Agent 开发里扮演什么对比
P0跨机守护进程把 Mac、Linux、云主机接成一个执行池。笔记本发起，重编译/长测试在服务器跑。本仓库实际就是 4 台机器在线。Claude Code 只在当前终端；Cursor 只能 SSH 一台；Devin 只在官方云沙箱
P0Worktree 隔离每个并行会话自动建独立 worktree 和分支，互不污染，用完回收。Cursor/Claude Code 是单目录模型；云端方案（Factory）要拉容器，冷启动慢
P0ACP 会话编排统一驱动 Claude Code、Codex 等 40+ CLI。主 Agent 能把子任务派给别的 Agent。Cursor Composer 不能跨进程派发；Devin 是黑盒，混不进你自己的订阅
P0持久任务总线长任务返回 operationId 就结束回合，后台跑完自动回执唤醒。不阻塞、不轮询。普通 MCP 调用是阻塞等待，长任务必超时
P1Diff 评审每轮改动可视化，代码行级批注直接回传给 Agent 当下一轮输入。Cursor 只能看本地 diff；终端 diff 没法行级评论
P1Agent Roles把机器+模型+权限+提示词固化为命名角色，团队复用。Cursor rules 绑单个仓库；CLAUDE.md 没法图形化分发
P1Magpie 集成一条命令导入本地 Magpie 的全部模型与路由组。原生 Claude Code 只认环境变量代理，没有路由组
P2定时任务 / Web 预览 / iOS 面板cron 巡检、远程 dev server 穿透预览、手机审批权限。同类工具基本没有横跨这三样的

独特优势

  • 真·多机拓扑：轻薄本当遥控器，4 台机器并行干活，同类做不到
  • 本地 worktree 隔离：没有容器冷启动，node_modules 天然共享
  • Loro CRDT 本地优先：断网可写，联网合流，不锁死在云端
  • BYOK 零加价：用你自己的订阅，它只收协同席位费（$8/人/月）

坑，先说清

  • 服务端闭源：多机同步依赖 lody.ai 云，不能完全自建
  • E2EE 还没上线，敏感代码经它中继要有心理预期
  • 单机单人用它属于过度设计，运维成本大于收益
  • 长尾 ACP Agent 兼容性参差，Claude Code/Codex 是一等公民，其他有坑

Magpie：模型路由

MIT 开源、Go 写的本地网关，15MB 单文件。所有 Agent 的模型请求都从这里过。 仓库：https://github.com/yetone/magpie。

优先级板块在 Agent 开发里扮演什么对比
P0协议互转网关OpenAI/Anthropic/Gemini 三套协议双向无损转换，流式、Tool Call、Thinking 全保真。Claude Code 要 Anthropic 协议、Codex 要 OpenAI 协议，底层同一个 DeepSeek。LiteLLM 是 Python 后端件，重；OpenRouter 是云端闭源、抽成
P0外科手术改配置自动识别 20+ 款 Agent（Claude Code、Lody、Zed…），保留注释缩进原子改写配置。断开一键复原。环境变量方案在 IDE 插件里不生效也难持久化
P0路由组容灾group/* 聚合多模型，smart/order/rotate 调度，429 自动冷却切换。长任务不被单一供应商打断。NotDiamond/Unify 管质量路由，不管配额和熔断
P1订阅桥接拉起官方 claude CLI 做双向管道，把 Claude Pro/Max、ChatGPT Plus 转成标准 API 用。包月变 API。裸抓 Token 重放的脚本风控封号风险大得多
P1Lody 导入magpieImport 协议，Lody 一键读取全部供应商与路由组。手工分发 .env 密钥满天飞
P1本地用量账本usage.jsonl 记每笔请求的 TTFT、Token、缓存命中、费用。数据不出本机。Helicone/Langfuse 要把全量 Prompt 发云端
P2本地脱敏出站前把密钥/邮箱/人名换成占位符，响应流式还原。厂商只见哈希。云端防泄露网关先拿到明文，已经晚了

独特优势

  • 改配置不留痕：20+ Agent 一键接管/复原，注释缩进都在
  • 订阅桥接走官方 CLI 子进程，不是重放 Token，风控特征最像真人
  • 三协议无损热转，单二进制无运行时依赖
  • 零成本零抽成：软件免费，账单就是你自己的 API 账单

坑，先说清

  • 订阅桥接在 ToS 灰色地带，高频批量分发有封号风险——生产环境用正规 API Key
  • 本机单点：Magpie 一挂，所有走它的 Agent 全部断连
  • 企业级鉴权/审计/多节点高可用没有，那类场景换 LiteLLM
  • 协议转换会磨损厂商特有参数（如超长 Thinking 预算的细节）

Nowledge Mem：记忆

本地优先的记忆与上下文层。CLI 已 Rust 化（本机 v0.10.111），核心 Server 闭源商业化。 仓库：https://github.com/nowledge-co/nowledge-mem。

优先级板块在 Agent 开发里扮演什么对比
P0会话注水SessionStart hook 把工作记忆简报注入新会话：项目角色、近期动态、待办。新会话不再是失忆开局。mem0 是嵌入式 SDK，要写代码集成；Letta 是黑盒记忆虚拟机
P0持久记忆nmem m add/search，8 种 unit_type（decision/boundary/…），BM25+向量混合检索，带重要度和标签。Claude Code 原生 memory 是纯文件无检索；Zep 面向聊天机器人场景
P0Space 隔离每个项目一个 Space，检索严格限定在 Space 内。跨项目记忆不串味。通用记忆库通常是全局单池，要靠标签自己分层
P0混合检索fast_bm25_vector，关键词+语义双通道。fast 模式日常用，strict 模式守门时用。纯向量检索对代码符号/命令名召回差，BM25 补这个
P1线程存证与蒸馏对话全文存 Thread，事后 distill 提炼成记忆。写前先检索去重。多数记忆插件只存不炼，记忆库越用越脏
P1规则与技能Space 级 Rules 注入纪律；技能匹配闭环（匹配→使用→反馈结果）。CLAUDE.md 是单文件静态注入，没有匹配和反馈
P2虚拟文件系统 / 远程访问 / 启动器Nowledge FS、跨机器取记忆、⌘⇧K 全局唤起。加分项，非刚需

独特优势

  • 专为多 Agent 开发设计：Agent Identity + Space + 角色守门，不是聊天记忆改造
  • ADR 级记忆质量：unit_type 枚举强制你写"决策"而不是"日记"
  • 蒸馏闭环：对话是证据，记忆是结论，两者分开存
  • 本机实测 3 个月：这个仓库的守门规则就活在里面

坑，先说清

  • 冷启动注入吃 token：简报+规则每会话固定开销，简报要控制长度
  • 复杂多跳检索（三度关系）能力有限，别当图数据库用
  • 并发写有 SQLite 锁风险，多 Agent 同时写要串行
  • 核心 Server 闭源：CLI 开源但完整服务端不能自建

三个怎么接成一条链

衔接点只有三个，每个都很薄——薄到一条命令或一个协议。这正是它们能长期共存的原因：谁也不改造谁。

    Nowledge Mem（记忆层）
      │ ① 注水：会话启动，简报+规则自动进入上下文
      ▼
    Lody（调度层）
      │ ② 派活：主 Agent 把子任务派到多机的 worktree
      │ ⑤ 验收：Diff 行级批注 → 回传 → 重跑
      ▼
    Magpie（路由层）
      │ ③ 降本：探索用 free 组，正式生成用 opus 组
      │ ④ 保活：429 自动切换，长任务不中断
      ▼
    上游模型（Claude / DeepSeek / GLM / 订阅）
三个衔接点。① 记忆注水：Nowledge Mem 的 hook 独立于 Lody 工作，任何 Agent 会话（包括 Lody 派发的）启动时都拿到简报。② 模型导入：lody agent-config import-magpie 一条命令，Lody 的模型选择器里直接出现 magpie/* 全部路由组。③ 经验沉淀：验收会话里产生的决策（为什么这么做、哪个坑踩过）用 nmem m add 写回记忆，下次注水就有了。

反过来说，三个不要接的地方：不要让 Nowledge Mem 存业务数据（它是开发记忆，不是产品数据库）；不要让 Lody 管生产部署（它是开发态平台，产物走 Git PR 进 CI）；不要在生产环境依赖 Magpie 的订阅桥接（ToS 风险 + 本机单点）。

SOP：一个特性从想法到合并

以"给 Agent 加一个新工具"为例。每一步标了谁在场。

#步谁在场做什么为什么
1开工Nowledge Memnmem m search "相关主题" 先查旧账：有没有做过、为什么放弃、当时的决策是什么。避免重复造轮子，避免推翻三个月前有理由的决策
2想清楚人 + 任意 Agent写 spec：改哪个动作、怎么验收。关键决策当场 nmem m add，带 importance 0.8+。决策不落盘，两周后必然重新争论一遍
3派活Lody主会话 lody_session_create 派子任务到远程机器的 worktree；批量任务用 chat_many。立即返回，不阻塞当前会话。并行 3 个修复互不污染；笔记本合盖也不影响远程跑
4选模型Magpie探索/讨论会话用 magpie/group/auto-*free；正式生成切 opus 组。Magpie 负责 429 时自动换道。探索阶段烧的是免费/便宜 token，正式生成才用贵的
5验收人 + LodyDiff 页逐行看，意见写在具体行上回传。Agent 拿着行级上下文重跑。数字对不对，跑 eval（这是本仓库的铁律：单测绿不算完）。验收意见不再是一句"改一下"，而是带行号的精确输入
6沉淀Nowledge Mem合并后蒸馏本线程：nmem t search 可查全程；重要教训 nmem m add（含"下次别怎么做"）。下次同类任务的第 1 步自动命中这次的教训
SOP 的两条红线。① 第 1 步的检索不能省——记忆库里的旧决策不查就是不存在，这是"找不到≠不存在"的镜像错误。② 第 6 步写记忆前先检索去重——重复记忆会让第 1 步的检索质量退化，最终整条链失灵。

Playbook：组合技与场景

组合技怎么做价值
多机并行修 Bug一个会话派 3 个 worktree 会话到 3 台机器，各修一个 issue，全部走 free 路由组跑通，最后你只验收 3 个 diff。人只出现在派活和验收两头，中间全是机器
贵模型只花在刀刃Magpie 建 group/auto-beam-free（探索）+ opus 组（生成）两个路由组。Lody Role 里锁死：评审角色用 opus 组 high 推理，跑腿角色用 free 组。同一份工作，token 成本差一个数量级
跨机器接力白天在笔记本上和 Agent 讨论方案；晚上把实现派给 Mac mini 跑长测试；手机上收 iOS 通知审批权限。第二天简报里已有昨晚结论。机器各干各的强项，你只做决策
记忆驱动的守门本仓库的做法：把架构红线（依赖单向、schema 单源、eval 即 spec）写成 Nowledge Mem 的 Space 规则，每次会话注水自动进场。守门规则不靠自觉，靠注入
降本验证改完路由组配置，跑 magpie usage 7d 对比改前改后的单任务成本和 429 次数。降本不靠感觉，靠本地账本
长任务不盯梢重构派给远程机器后结束回合。Lody operation 完成时自动回执唤醒；Magpie 在后台默默处理了 2 次 429。你睡你的，链路自己会活

什么时候这套组合是错的

  • 单人单机单任务：直接终端跑 claude 更顺。Lody 的调度价值来自多机多任务，没有这个前提就是纯负担。
  • 生产环境：Magpie 订阅桥接有 ToS 风险、本机单点不可高可用。生产走正规 API + 企业网关（LiteLLM/Kong）。
  • 对外产品内嵌记忆：Nowledge Mem 是开发者自己的记忆，不是给最终用户的多租户记忆方案（那类场景用 mem0/Zep 的 SDK）。
  • 需要审计合规的团队：三者都以本地/闭源服务为代价换轻量，等保、SOC2 类硬要求出现时，这套组合要重新评。
