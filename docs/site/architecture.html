全产品架构全景图

本仓库承载两条核心 Agent 产品线（Recipe Agent 品牌视频克隆生成与 Main Agent 方法论与数据咨询）、一套可执行的方法论门禁（ANB 7+1 阶段与 8×8 数据矩阵），以及本地开发态三件套（Nowledge Mem + Lody + Magpie）。

架构三条死律。
1. 依赖单向不可逆：apps/workbench 与 apps/bot-gateway 严禁互相 import，只能单向调用 packages/core 或 packages/consult；packages/shared 零内部依赖。
2. 三大唯一真源：领域对象唯一真源在 packages/shared（Zod 边界强校验）；四个品牌护栏唯一真源在 packages/core/src/seed/brands.ts；生命周期阶段唯一真源在 work/schema.yml。
3. 分层归因铁律：修复 Agent 质量问题严格按 eval → data → tool → prompt 顺序排查，严禁跳过底层数据与工具契约直接改提示词。

二、五层架构职责与边界对账

每一层只做自己的事，跨层越界（如在评测夹具里复制品牌档案、在工具 handler 里抛异常）一律视为架构缺陷。

架构层级核心包 / 目录核心职责硬性护栏与禁令
L1 交互入口层 (Surfaces)apps/bot-gateway · apps/workbench · docs/site飞书长连接/Webhook 异步回执与会话分桶；Operator 审查台（Next.js）；ANB 静态知识门户（29 生成页 + 8 原始档案）。严禁任何 Surface 直接调用大模型 API，所有执行必须经过底层 Runtime；Surface 之间严禁互相引用。
L2 核心双引擎层 (Engines)packages/core · packages/consultcore：run-agent.ts 单文件主循环（步数记录、双层预算熔断、modelUsage 累计计费、ok/err/guard 值语义工具）；consult：20 节点 + 17 路由能力图谱、BM25 物理化知识包与五段式 grounded 合成。run-agent.ts 的主循环严禁拆碎到多模块；工具 handler 严禁 throw 异常，失败必须返回 isError: true 的值。
L3 契约、适配与评测底座packages/shared · packages/feishu · packages/evalsshared：Zod 领域模型（BrandProfile / ReferenceVideo / Recipe / AgentRun）；feishu：事件验签解密、post 富文本与卡片格式化；evals：14 用例 + 15 确定性规则 + Rubric 裁判。packages/shared 不得 import 仓内任何包；新增工具必须同步写入 createBrandTools 与 brandToolNames() 白名单。
L4 ANB 治理与数据矩阵层work/ · docs/product/ · scripts/work/ 八个寄存器（状态即目录，ls 即看板）；matrix.json（8×8 数据产品矩阵）与 tables.json（13 张样张表）；build.mjs 零孤儿页生成器。无检查器的契约只能标「约」不能标「验」；文档引用的数字必须通过 facts.mjs --check 对账。
L5 本地开发工具链Nowledge Mem · Lody · MagpieNowledge Mem 负责跨会话记忆注水与红线守门；Lody 负责 4 机执行池、Git Worktree 隔离与异步任务回执；Magpie 负责 127.0.0.1:3425 三协议互转与 group/* 429 容灾。开发态工具链不介入生产部署运行时；不在 Nowledge Mem 存业务数据。

三、核心跨模块调用与数据流向

业务流场景调用路径契约保障
飞书群提问 / TikTok 链接apps/bot-gateway → packages/core | packages/consult网关识别 TikTok 链接或 /recipe 指令走 core 异步生成管道（3s 回执 + 队列投递）；识别方法论/数据提问走 consult 引擎返回五段式结论。
