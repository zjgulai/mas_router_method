原始文档

八份 HTML，未改一字。它们是这套方法的原始产物，页面结构各不相同——因为写的时候是在解决具体问题，不是在设计一个站点。

这八份文档不遵循本站的导航结构，它们是独立的单页。你打开后会看到和下面列表不同的排版，这是有意的： 改它们会让「原文」变成「改编」，而这套方法的全部价值建立在可追溯上。

每份文档都在仓库里，路径见页脚。

失败图鉴 failure-atlas.html

七种误判：四类来自系统的假信号，三类来自你自己读它的方式。全部来自真实运行。

决策树 decision-tree.html

三个问题定位到你该在哪一步。含"怀疑有假信号"和"卡住了"两个额外入口。

术语表 terms.html

每个技术词三栏：它在说什么、坏了会怎样、你怎么一眼看出来。

能力图谱 capability-map.html

按六个能力域拆解一个真实 agent 产品：30 项能力、成熟度、以及逐条诊断。

方案 v0 anb-proposal.html

这套方法最初的设计：问题、五条原则（每条挂一个真实事故）、六步闭环、三件套分工。

实测一：七个问句够不够 atlas-test-report.html

用第一次实测检验七问句，发现它们漏了一整类：产出可用度。

实测二：用修正后的方法 anb2-report.html

用补过的四条质量问句做第二个产品，发现"检查通过但理由错"这一层。

实测二：完整六步 anb2-full.html

六步走完，三步没过。含观测污染、配额墙、以及阶段六规则被自己推翻。

它们之间的关系

文档在这套方法里的角色
能力图谱诊断：一个真实项目的现状，用来证明这些假信号是真的，不是想出来的。
失败图鉴核心：七种误判 + 七问句 + 四质量问句 + 读信号规则。这是整套方法最该读的一页。
决策树导航：不知道下一步时用。本网站的七个阶段页是它的展开版。
术语表翻译：把技术词翻成"坏了会怎样"。第三栏才是给人用的。
方案 v0原始设计：六步闭环的初版。本站的七阶段是在它基础上补了「设计」和「运营」。
实测一自我检验：用自己的方法检查自己，发现七问句漏了一类。
实测二（报告）修正验证：补齐后再做一次，发现补得对，但仍有一层漏。
实测二（完整）走完全程：六步都做了，三步的验收做不到，如实记录。
