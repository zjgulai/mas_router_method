# 实测二：换一个产品，验上一轮的修法

**状态**：已收尾。**需求阶段第 5 问的停止信号触发，按方法停机，产品不做。** 设计阶段未进入。
**目的不是做出第二个产品，是检验第一轮那十二处修法是否真的有效。**

---

## 事先写下的预测（可证伪）

如果只有一条要留，就留这一条——**跑完再定标准，等于没有标准。**

| 观察到的 | 结论 |
|---|---|
| 上一轮修过的地方**不再出问题**，缺口落在别处 | 修法有效。新缺口是正常的：一个产品只能暴露它撞得到的那部分 |
| 上一轮的缺口**又以新的说法出现** | 修法只治了症状。说明我修的是那一份材料，不是那一类问题 |
| 上一轮修过的**和新的混在一起，分不开** | 这一轮测不出结论。如实记下来，不硬下判断 |

具体盯三处，它们是上一轮最后补的、证据最硬的：

- **第 3 笔**：产出模板缺「它给你什么」→ 现在有了第六行和 exit test 第三维。
- **第 11 笔**：「拒绝清单」装不下内容 → 现在拆成禁令清单 + 应答规则表，六块。
- **第 12 笔**：没有东西检查几块互相成立 → 现在 exit test 要报「哪几块冲突」。

**这三处如果在新产品上又出问题，就是「只治了症状」。**

## 上一轮已知、本轮不重复的部分

- **INC-002**：挂载目录写后读不一致。**本轮所有验证在 `/tmp` 的克隆里做**，那里实测 0/60。
- **方法在上一轮被改过十二次。** 本轮跑的是打过补丁的方法——这是本轮的前提，不是缺陷，
  但它意味着**两轮的对比是「补丁前 vs 补丁后」**，不是「同一套方法的两次独立使用」。

## 测量工具（与上一轮相同，便于对比）

只记六类，当场记，不事后回忆：

1. 我不得不发明一个方法没描述的步骤
2. 我不得不跳过方法描述的某一步，因为它在这里做不到
3. 两份文档说法不同，我必须自己选一个
4. 我判断不出这一步做完没有——exit test 没有区分度
5. 我去用了方法没提到的工具或 skill
6. 我问了用户一个方法本该回答的问题

**不算洞的**：方法明确留给我判断的设计决定、我自己不够谨慎犯的错。

## 一条规矩：不许圆场

每次想替方法补台阶（「这里它大概是这个意思」），就停一下记一行。**圆场的地方就是洞。**

这也是上一轮唯一没法自动化的部分——第一轮十二笔里，绝大多数是在这种时刻被记下来的。

## 这一轮测不到什么（与上一轮相同，不重复解释）

- 测不了「一个陌生人能不能跟上」——用户是方法的作者。
- 测不了方法整体的 exit test——那是「一个真人用它做出了东西」，本轮仍然只有我们两个。

## 结论

### 这一轮的产出是一个「不做」

用户在第 5 问选的停止信号是：**如果归因做不了，就别做。**

问到实际数据时：平台物流数据分辨不出「卡清关 / 派送失败 / 买家没取 / 我们没发」这四者，
而运营靠的是**经验直觉**——产品继承不了，经验也写不成规则。**信号触发，按方法停机。**

**这是方法第一次真的拦下一个产品。** 上一轮的停止信号没触发（政策虽然散，但存在）。
这一轮触发了，而它拦下的是一个本来会被做出来、然后只能发通用消息的东西——
**而那正是用户一开始说要消灭的东西。**

### 事先写下的预测：第一行成立

预测表写的是：修过的地方不再出问题、缺口落在别处 → 修法有效。

**成立。** 具体：

| | 第一轮需求阶段 | 第二轮需求阶段 |
|---|---|---|
| 缺口数 | 4 笔（第 1、2、3、4） | **0 笔** |
| 唯一出现的模式 | 「全部同意」未被处理 | 「全部同意」被**上一轮加的规矩**处理，并产出了具体内容 |

第 3 笔（产出模板缺「它给你什么」）的修法在第二轮**没被触发**——因为这一轮的 exit test
带了第三维，而用户在第 4 问之前就主动说出了产物层面的事。

**但样本很小，而且有一个硬边界**：这一轮**没有进入设计阶段**，所以第 8、9、11、12 笔
（全是设计阶段的修法）**一次都没被压过**。特别是第 11、12 笔——它们证据最硬、
改动最大——**这一轮完全没验到**。

### 第二轮唯一的缺口，落在新的地方

第 1 笔：**方法对「停止信号」只要求它「可测量」，没要求它区分「人能做到」和「产品能做到」。**

用户第一反应是「平台数据里没有，但**运营判断得出来**」——听起来像「所以没问题」。
只有追问「他凭哪一条信息判断」，才露出真相是经验直觉。

**一个「人能判断出来」的证据，被读成了「产品能判断出来」的证据。** 方法是为人写的，
但这一问要的是产品的可行性，而它没有区分这两者。

### 两轮合起来

| | 第一轮 | 第二轮 |
|---|---|---|
| 产品 | 客服回复草稿（政策检索，无不可撤销动作） | 卡单催付（有真动作） |
| 走到哪 | 设计阶段三轮，exit test 未通过 | **需求阶段第 5 问，停机** |
| 缺口 | 12 笔 | 1 笔 + 一次成功的停机 |
| 方法拦下产品了吗 | 没有 | **拦下了** |

**第二轮不是「第二轮第一轮」**，因为第一轮跑完改了十二处。
所以两轮比的是**补丁前 vs 补丁后**，不是同一套方法的两次独立使用。这一点必须留着。

### 这次仍然没测到的

- **验收阶段两轮都没碰到。** 它是方法唯一的硬门，而两轮都停在了它前面——第一轮因为
  设计过不了 exit test，第二轮因为产品被停机。**这是两轮累积下来最大的空白。**
- **设计阶段的后四处修法没验过**（见上）。
- 测不了「一个陌生人能不能跟上」——用户是方法的作者。

### 这一笔值得单独说：修法在真实使用里生效了

上一轮加的规矩是——**「全部同意是一个信号，不是成功」，这时要停下来问一个只有他能给的具体事实。**

这一轮它被触发（三问三中），被应用，而且**产出了一个有内容的东西**，而不是又一次同意。
上一轮同一位置的产出是「经得起」。

这是两轮里第一次出现「上一轮的修法在新产品上被验证」。**但样本只有一次**，不足以说它总是有效。
留着看后面几问还灵不灵。
