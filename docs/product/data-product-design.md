# 数据产品方案：Momcozy 声量 → GMV 归因

**状态**：设计中。结论层与指标层已定，其余六层待议。
**决策**：品牌在分配区域资源（社媒、PR 预算）。
**窗口**：1 年。**GMV 来源**：内部 ERP。**外部数据**：Apify 全量 actor。

---

## 设计顺序（与建造顺序相反）

结论层 → 指标层 → 打标层 → 采集/存储 → 呈现/报告

理由来自本项目自己的实测：两轮真实试跑都因「产出物没定义清楚」而停。自底向上建到一半
才发现底层支撑不了上层，是数据产品的典型死法。

---

## 零、三个前置发现

### F1 决策缺一个自变量：预算投放数据

决策是「区域资源分配」，而当前给到的数据是 **GMV + 订单（ERP）+ 外部声量（Apify）**。

这三样能算出**声量 → GMV 的弹性**。但**「预算 → 声量」这一段是空的**。

后果很具体：如果只能算出「区域 A 的声量弹性比区域 B 高」，决策者拿到手仍然不知道
该往哪投——因为**不知道加一块钱预算在 A 和 B 分别能买到多少声量**。弹性高不等于
投放便宜：A 可能弹性高但获客成本极贵，B 弹性低但便宜。

**需要的数据**：按区域 × 渠道 × 周 的**花费**（社媒投放、PR、达人佣金、Amazon PPC）。
不一定是 ERP 里，可能是代理商账单、平台后台、财务成本中心。

**没有它**，产品只能做到 C1–C3（关联与滞后），做不到 C4（预算边际回报）。
而**决策需要的恰恰是 C4**。

### F2 区域面板改变了识别策略——这是好消息

原方案最大的隐患是伪相关：声量与 GMV 都随时间上升，两条带趋势的序列必然得到 0.9 的
假相关。

**但决策的单位是「区域」，不是「品牌整体」。** 这把问题从单条时间序列变成了
**区域 × 周的面板**。而面板允许一个更强的估计：

```
ln(GMV)_{r,t} = β · ln(声量)_{r,t-k}
              + 区域固定效应 α_r        ← 吸收区域规模、成熟度、基线差异
              + 周固定效应   λ_t        ← 吸收全球趋势、季节性、平台算法变动
              + 控制变量      X_{r,t}    ← 促销、价格、缺货、竞品
              + ε_{r,t}
```

**周固定效应把「两条都上升」这个共同的趋势整体吸收了。** 剩下的识别变异是
「**同一周里，区域 A 的声量比区域 B 涨得多，之后 A 的 GMV 是否也比 B 涨得多**」。

这是十年窗口内唯一站得住的识别策略，而且它把伪相关问题从「致命」降级为「已处理」。

**代价必须说清**：全球性的事件（一次全球投放、一次全球性病毒视频）会被周固定效应
完全吸收，**测不出来**。产品只能回答**区域差异化的效应**，不能回答「全球声量总共
带来多少 GMV」。这是设计约束，不是缺陷。

### F3 缺货是最危险的混淆变量

母婴品类断货常见。机制：**缺货 → GMV 掉，而声量还在涨** → 回归给出「声量有害」。

方向性误导，而且它不会以「数据缺失」的样子出现——它看起来像一个真实的负相关。

**必须拿到**：按区域 × SKU × 周的**可售库存天数**或**断货率**。来源是 ERP / 仓储。
这一列如果拿不到，模型结论全部不可信。

## 一、结论层

结论不是「洞察」。一条结论必须**可被证伪**，并且**指向一个决定**。

### 结论卡格式（每一条都必须长这样）

| 字段 | 要求 |
|---|---|
| 主张 | 一句话，含量化，不用形容词 |
| 范围 | 哪个区域、哪个时间窗、哪个品类 |
| 区间 | 置信区间，不是点估计 |
| 依据 | 哪些指标 + 血缘（可下钻到原始记录） |
| **证伪条件** | **什么情况这条结论作废** |
| 决策含义 | 会改变哪个动作 |

### 四条结论

**C1 区域弹性排序**（决策：预算倾斜）
> 控制促销、价格、缺货后，声量每提升 10%，区域 A 的 GMV 提升 a%（区间 b–c）；区域 B 为 d%。
> **证伪**：某区域有效样本 < 阈值；或存在未控制的本地事件（本地大促、本地竞品价格战）。

**C2 滞后结构与峰值**
> 声量变动对 GMV 的效应在第 k 周达峰（区间 k₁–k₂），区域间峰值不同。
> **证伪**：滞后曲线无峰（单调下降或噪声）→ 说明没有可识别的传导，这条结论不成立。

**C3 单次声量事件的增量 GMV**（决策：复盘某次投放）
> 某次声量跃升（某周偏离基线 > xσ）带来增量 GMV y（区间），相对同期未受影响的区域。
> **制**：同期存在其他未控制事件（新品上市、平台活动）。

**C4 预算边际回报**（决策：直接决定预算分配）
> 每增加 1 单位声量所需花费，与由此带来的 GMV 增量之比，按区域排序。
> **前置**：F1 的预算数据。**没有它，C4 不存在。**

### 一条硬性纪律

**C1–C3 是关联，C4 才是因果。** 产品界面上必须永久标注这个区别。
把关联说成因果，是这个品类最常见、也最贵的错误。

## 二、指标层

### 指标卡格式

每个指标必须有八项，缺一项就不许进产品：

```
指标名 | 可执行定义 | 粒度 | 单位 | 数据源 | 口径版本 | 已知偏差 | 什么时候不可用
```

最后两项是重点：**「已知偏差」和「什么时候不可用」**。这是把失败图鉴第七类
（数的不是你以为的那个）写进指标卡本身。

### 三族指标

#### A. 声量族（外部，Apify）

| 指标 | 定义 | 关键偏差 |
|---|---|---|
| A1 提及量 | 按源 × 区域 × 周的帖子/评论数，去重后 | 已删内容永久缺失 → 系统性偏低 |
| A2+ 正面加权互动量 | 情感为正的内容，按赞×1 + 评×3 + 转×5 加权（权重需标定） | 只有当前值，无法回溯当时值；**权重未标定时该数字不可比** |
| A2− 负面加权互动量 | 情感为负的内容，同上加权 | 同上。**负面内容传播更快**，不拆开会把两种相反的效应混成一个系数 |
| A3 声量份额 SOV | 品牌提及 / 品类总提及 | 分母依赖**竞品集定义**，换一套就变 |
| A4 情感净值 | (正 − 负) / 总，按打标结果 | 母婴品类反讽与口语极难判，误差高 |
| A5 内容构成 | UGC / 官方 / 达人 占比 | 「达人」判定依赖粉丝阈值，阈值是任意的 |
| A6 峰值事件 | 周偏离滚动基线 > xσ | 阈值 x 改变结论数量，必须锁定并版本化 |

**A2 必须拆成两条，这是本层最关键的一处修正。**

直觉是「情感越好，声量越有价值」。实际相反：**负面内容传播更快、互动更高**。母婴品类尤其——
一个「用了过敏」的帖子，互动量可能是正常帖的 5 倍。

后果很具体：不拆，**负面事件会被算成声量跃升**，而它对 GMV 的影响大概率是负的。
回归会把「正面带动」和「负面损伤」压进同一个 β，得到一个大而含混、无法解释的数。

**A 族最大的未解问题：区域归属。**
一条 TikTok 帖子是哪国的？可用信号：作者位置（常缺）、语言（会错）、hashtag、
提到的本地零售商、评论货币。**归属误差会直接进入自变量的分母。**

如果区域归属不可靠，**区域决策就无法支撑**——这是第二轮讨论必须先解决的问题。

#### B. GMV 族（内部 ERP，口径可控）

| 指标 | 定义 | 必须定死的地方 |
|---|---|---|
| B1 GMV | 按区域 × 渠道 × SKU × 周 | **净额还是毛额**。跨境退货率高，两者差异极大 |
| B2 订单数 / 客单价 | 同上 | 拆单、合单如何处理 |
| B3 新客 / 复购拆分 | 按首次购买判定 | **声量对新客的影响远大于复购**，不拆会把效应稀释 |
| B4 退货率 | 按周回溯归因 | 退货有滞后，与销售周不同期 |

**B3 是最容易被跳过、但最影响结论的一项。** 声量拉的是新客，复购是留存的结果。
混在一起，弹性的解释就错了。

#### C. 控制变量族（缺一条，结论就不可信）

| 变量 | 来源 | 不控制会怎样 |
|---|---|---|
| C1 促销日历 | 运营 | 大促同时抬高声量与 GMV，效应被错误归给声量 |
| C2 价格 / 折扣深度 | ERP | 降价同时抬 GMV 与声量（打折内容多） |
| C3 **可售库存 / 断货率** | ERP、仓储 | **缺货 → GMV 掉而声量涨 → 得到「声量有害」的荒谬结论**（见 F3） |
| C4 竞品声量与促销 | Apify | 竞品大促会同时压低本品 GMV、抬高品类声量 |
| C5 新品上市 | ERP | 上市自带声量与 GMV 双峰，是典型的伪因果 |
| C6 Amazon PPC 花费 | 平台后台 | 站内广告直接推 GMV，不控制则算进声量头上 |

## 三、1 年窗口的统计现实

必须算清这笔账，否则会做出一个「技术上跑通、统计上无意义」的产品。

**样本结构**：区域数 R × 52 周。
- R = 5 → 260 个观测（但按周聚类，有效 N 更小）
- R = 3 → 156 个观测，加固定效应和控制变量后已到边缘

**滞后识别**：周频、1 年 = 约 26 个双周周期。要识别 2–4 周的滞后，勉强够；
要识别 6 周以上的滞后，**不够**。

**结论**：1 年窗口能支撑 C1、C3；C2 只能给粗略的滞后区间；**C4 需要预算的时间变异**
——如果一年里预算分配只调整过一两次，那就没有识别力，只能做描述性对比。

**如果一年内预算基本没变**，诚实的说法是：这个产品当前只能做**诊断**
（哪个区域的声量- GMV 关系更强），不能做**归因**。而诊断仍然有用，只是不能说成因果。

## 三·三、采集层（三轮讨论，已定）

### 比「快照不是历史」更严重的问题：抓取时滞

快照不能回溯是工程问题。但有一个统计问题跟它无关，而且更危险：

> 同一个帖子，每次抓到的互动量都不同，而且**随时间单调增长**。

于是：**如果不同区域的帖子抓取时点不同，「声量」里就混进了抓取时滞。**
美国帖子是两周前抓的、德国是今天抓的 → 德国数字天然更高 → 把「刚抓的」误读成「更热」。

危险之处在于：**区域正是要比较的单位**，而这个错误不会报任何错，看起来完全正常。

### 三条处置（按重要性）

**一、每条记录存两个时点：抓取时点，和「首次见到」时点。**
后者更关键。以后一切「当期值」以**首次见到**为锚，不以最后一次抓取为准。

**二、互动量折算到统一的「帖子年龄」。**
帖子发布后 t 天的互动量遵循相对稳定的增长曲线。用同源数据拟合基准曲线，
把每条折算到同一年龄上。**不做这一步，跨区域比较不成立。**

**三、抓取按固定节奏，不按需触发。**
如果抓取是由「有人看报表」触发，这个动作本身会污染数据——即图鉴第六类，测量污染。

### 其余三条

**增量与全量分开。** 全量建基线，增量跟变化。混在一起的结果：全量跑一次成本失控，
只跑增量永远建不了基线。两类各有跑批频率，存储里能区分。

**去重必须在跨源层面。** 内容会被搬运、重发、裁剪后重发。靠 URL 去重不够，
要内容指纹（相似文本 + 同一视频的感知哈希）。不去重，声量被同一内容重复计数。

**保留原始载荷。** 不要把 Apify 返回清洗完就丢。行业普遍教训：半年后一定需要
当初扔掉的字段。压缩存原始载荷，成本远低于重抓。

## 三·四、打标层（三轮讨论，已定）

### 核心不是标签，是版本

现有 `HookPattern` 是七个 enum 写进 schema。在开发流程里没问题，在数据产品里是灾难：

**改一个标签，历史全部不可比。** 今天把 `problem-agitation` 拆成两个，去年 52 周的数据
就和新数据不是一个体系——而基于它算出的「情感净值」「声量构成」会在某一点出现台阶。

### 三条

**一、标签体系带版本，旧数据不重写。**
每条标注记录存 `taxonomy_version`。查询时要么按版本分组，要么显式映射，**绝不静默合并**。

**二、每条标注带置信度。**
情感尤其重要：母婴品类的反讽、口语、妈妈群体黑话，模型误差大。只有置信度存在，
敏感性分析才做得了——而敏感性分析是判断「结论稳不稳」的唯一手段。

**三、金标准集，必须人工标。**
每个标签抽 200–300 条。用途：标定模型准确率、监控漂移、比较两版模型。
**没有金标准集，你永远不知道标签准确率是多少**；不知道准确率，下游洞察全部无法被信任。

**标注一致性要算。** 两人标同一批，Kappa 低说明标签定义本身有歧义，不是标注员不行。

### 两层之间的一处耦合（容易漏）

**打标结果会反过来影响区域归属。** 一条帖子若被标为「抱怨物流」，它大概率提到本地物流商
——那是区域线索。

所以不能「先归属再打标」，**两者互为输入**。至少跑两轮：
粗归属 → 打标 → 用打标里的本地化线索修正归属。

这也是归属必须有版本、允许重算的原因。

## 三·五、区域归属方案（二轮讨论，已定）

**要解决的是什么**：决策单位是「区域」，而外部声量的区域归属是推断出来的，
误差会直接进入自变量的分母。这是整个产品最脆弱的一环。

### 命名空间：四类，永不合并

| 值 | 含义 | 处理 |
|---|---|---|
| `region` | 已归属到某个市场（ISO 3166 国家码） | 进自变量 |
| `unattributable` | 内容存在证据，但证据互相矛盾，无法判定 | **不进自变量**。单独成序列，用于观测采集/打标质量是否劣化 |
| `insufficient` | 证据不足以判断（无位置、无本地化特征） | 同上。与上一条分开，因为**补数据能救后者，救不了前者** |
| `not_applicable` | 声明本身不属于任何区域（如全球官方发布） | 排除并记录 |

**为什么必须四类而非「区域 + unknown」**：`unattributable` 和 `insufficient` 的处置相同、
但**成因完全不同**。合成一类就再也分不清「我们的算法不行」还是「这条内容真的没线索」——
而这两者的动作相反。

### 纪律（三条，不可协商）

1. **`unknown` 永不摊派。** 不按人口比例、不按 GMV 比例、不按已有分布重分配。
   摊派会制造一个「完整但错」的分母，而它看起来没有任何问题。
2. **置信度随记录永久保存。** 不进聚合后再补——历史记录的置信度补不回来。
3. **归属版本号随记录保存。** 归属规则改一次，版本加一。否则跨期比较时
   「声量涨了」分不清是市场变了还是算法变了。

### 一期：规则归属（浅方案）

**多信号加权投票**，按后验一致率给权重：

| 信号 | 初始可靠度 | 说明 |
|---|---|---|
| 帖子自带的 location 字段 | 0.70 | TikTok 少、IG 有 |
| 商品链接的域名 / ASIN 市场 | 0.95 | `.co.uk` / `.de` / `.co.jp`，ASIN 归属市场确定 |
| 品牌自己的国别 hashtag | 0.90 | `#momcozyuk`，最好用 |
| 提到本地零售商 | 0.75 | "buy at Target" 强于语言 |
| 货币符号 / 尺寸单位 | 0.70 | 需抓评论 |
| 语言 | 0.55 | 母婴大量英语帖来自东南亚、印度、欧洲 |
| 作者 profile 明写地区 | 0.90 | 最可靠但覆盖率低 |
| 发帖时间与本地作息 | 0.30 | 仅辅助 |

**权重不是拍脑袋的**：先用**锚点集**标定——品牌自己在各国官方账号的帖子，
归属确定无疑。用它算每个信号的实测一致率，作为初始权重。成本不到一天，
比任何直觉都可靠。

**阈值**：置信度 < 0.6 → `insufficient`；多信号指向不同区域且票数接近 → `unattributable`。

**覆盖率现实**：母婴类约 **55–70%** 能明确归属。

### 二期：内容 + 行为 + 联合校准（保留，不急）

**第一层 内容增强**
- 评论区本地化证据（配送询问、货币、自述位置）——**评论是归属的金矿**
- 图片/视频 OCR：包装警示语的语言、成分表本地法规格式、**条码 EAN 前缀直接是国别**
- 商品链接解析：域名与 ASIN 市场

**第二层 行为网络**（最深、也最有效）
- 账号粉丝的地理结构（需 actor 拉 follower 样本，成本高）
- 转发/引用网络的地域聚集
- **同账号历史帖一致性**：同一账号通常服务一个市场。用历史归属做先验，
  **这是性价比最高的一条**

**第三层 联合校准**
把「声量 × 归属权重」按区域加总，用内部 GMV 的区域结构反解归属参数。
这不是循环论证——归属参数由内容特征识别，校准目标是时序结构，识别变异不同。
行业里叫 calibration against a known aggregate，是官方统计处理抽样权重的标准做法。

**深方案的三个代价，必须一起记**
1. 覆盖率可到 80–88%，但需要 follower 采样 + OCR + 历史累积
2. 精度提升主要发生在边界情况（一个英语帖算美国还是印度）
3. **隐性风险**：校准到 GMV 之后，声量与 GMV 的部分相关性是人为构造的，
   做归因时必须扣掉。很多团队踩过这个坑。

### 什么时候才做二期（明确门槛，不凭感觉）

两件事**同时**成立：
- 一期结论在 `confidence > 0.8` 子集上不稳定（说明归属误差确实影响结论）
- 或者按区域决策的预算规模已经大到值得

否则二期是过度工程。

### 验收标准（一期）

- [ ] 锚点集一致率 ≥ 0.85（锚点 = 品牌官方账号帖子，归属确定）
- [ ] 明确归属覆盖率 ≥ 55%，且 `insufficient` / `unattributable` 分开统计
- [ ] 按置信度分层（<0.6 / 0.6–0.8 / >0.8）分别算 C1，结论方向一致
- [ ] 归属规则版本号存在于每条记录上，且改版后旧记录不被重写

## 四、呈现层与报告层（四轮讨论，已定）

### 区别不是形式，是谁发起

| | 呈现 | 报告 |
|---|---|---|
| 谁发起 | 人问，它答 | 它主动给 |
| 回答什么 | 「A 区上周声量多少」 | 「你应该把预算从 B 挪到 A」 |
| 成功标准 | **能被核实** | **能被证伪** |
| 失败形态 | 数字对不上，人不再信 | 结论漂亮但没法验证，人不再看 |

**行业里最常见的产品，是把报告做成了呈现**：一个 dashboard，几十个图表，等人自己去找结论。
那不叫报告，那叫**把最难的活留给本来就很忙的人**。

### 呈现层：唯一的硬要求是可下钻

每条路径都必须能走到原始记录。不是为了好看，是因为要判断「这个数可不可信」——
而可信度只能靠看它的来路。

**纪律一：零聚合不可省。** 每个聚合数字旁必须能一键看到构成它的记录。
先聚合再丢明细，半年后发现某个数不对，**已经查不了了**。

**纪律二：口径显示在数字旁边，不藏在文档里。** 跨境尤其——GMV 是否含税、是否含运、
退货什么时候扣、汇率用哪一天的。数字旁不写口径，等于让人猜。

**纪律三：三态可见。** 数据到了 / 数据错了 / 无法判断。第三态必须单独显示，
因为**采集失败会被默认读成「今天没有异常」**，而这两件事的动作相反。

### 报告层：单位是结论卡，不是周报

每条卡必须带齐六样：主张、范围、区间、依据、**证伪条件**、决策含义。

**「证伪条件」是报告层和「又一个 dashboard」之间唯一的分界线。**
不写证伪条件的结论无法被推翻，也就无法被信任——它只是意见穿了一件量化外衣。

**报告要主动报「这条不成立了」。** 做法：结论卡落库时，把证伪条件写成**可执行的检查**；
每周跑一次，成立标绿、触发标红，并说明触发了哪一条。

这是仓库现有机制的直接迁移：设计记录里的「什么情况说明这个设计错了」已经用了两轮、
证明有效。**报告层就是同一个机制用在结论上。**

## 五、三根柱子（四轮讨论，已定）

最后讲，因为要等所有层定了才知道它们该管什么。

### 口径层

**每个指标有且只有一个定义，带版本。**

不是文档里写一段，而是**指标卡带版本号，且进存储**。跨境最容易翻车的地方就是
「同一个词在两个渠道含义不同」——不钉死，两个报表永远对不上。

**关键设计：口径变更时旧数据不重算，新数据带新版本。** 界面必须显示「这个数字用的是哪版口径」。
看起来丑一点，但它防的是最贵的一种错误：**跨期比较时把口径变更读成了业务变化**。

### 质量层

三态，且**第三态要被统计**。每层各管一件事：

- 采集层：这个源今天有没有抓到
- 打标层：金标准集准确率有没有漂
- 指标层：今天的分母是不是异常小

**「无法判断」必须单独计数并展示。** 它是唯一一个能静默变成「一切正常」的状态——
这个仓库已经踩过三次同类的坑（检查静默停止、断言空转、计数变 0）。

### 血缘层

**结论 → 指标 → 标注 → 记录 → 原始来源。**

它是报告层「依据」那一栏的支撑。没有它，结论卡里的「依据」只是一个链接，不是一条可核实的路径。

**验收标准很具体**：从任一结论出发，能一路点到原始载荷，中途每一跳都显示它用了
哪版标签体系和哪版口径。**做不到这一点，血缘就只是宣称。**

## 六、四条决定（四轮讨论，已定）

1. **报告的最小单位是结论卡，不是图表。** 每条卡带证伪条件，且证伪条件变成每周自动跑的检查。
2. **呈现层每个聚合数都必须能一键下钻到明细。** 做不到的数字不许上线。
3. **口径变更时旧数据不重算，版本号随数字走。**
4. **三态里的「无法判断」必须单独计数并显示。**

## 七、前置验收：区域间声量相关性（必须在动手前测）

**这是全案唯一的致命风险，而且两周数据就能估出来。**

识别策略是「周固定效应吸收共同趋势，用区域差异识别」。它成立的前提是
**各区域声量有足够的独立变异**。但跨境品牌不是这样长起来的：

> 一条美国达人视频会在德国被看到；一次全球 KOL 投放会在所有区域同时起声。

如果各区域声量变化高度同步，**周固定效应吸收掉的正是信号本身**。

| 区域间声量相关系数 | 判定 | 动作 |
|---|---|---|
| < 0.5 | 面板识别成立 | 继续，方案可行 |
| 0.5 – 0.8 | 边界 | 继续但必须报「有效变异有限」，结论只到 C1/C3 |
| > 0.8 | **识别不成立** | **停**。1 年窗口内做不了区域归因 |

**怎么做这个检查（不到一天）**：取两个月的 Apify 数据，按区域算周度提及量序列，
算区域两两相关系数矩阵。用**同一批次**抓取的数据，避开 §三·三 的时滞问题。

**如果 > 0.8，诚实的结论是**：1 年窗口内这个产品只能做品牌整体时间序列，
而那条路依赖外生冲击（某次投放开始、某条视频爆了），**不是面板能解决的**。
那时我会直接说「做不了」，不给一个看起来完整、实则无识别的方案。

## 八、整体方案

### 8.1 能回答什么，不能回答什么（给决策者的一页）

**能回答：**

| 结论 | 依赖 | 前提 |
|---|---|---|
| C1 区域弹性排序 | 区域面板 + 固定效应 | §七 相关性 < 0.8 |
| C2 滞后结构 | 同上 | 1 年约 26 个双周周期，识别 2–4 周可行，6 周以上不可行 |
| C3 单次事件增量 GMV | 偏离基线的声量事件 | 同期无其他未控制事件 |
| C4 预算边际回报 | **预算数据（已确认拿得到）** | 预算在 1 年内有足够时间变异 |

**不能回答：**

- **全球声量总共带来多少 GMV** —— 被周固定效应吸收，这是设计约束不是缺陷
- **因果**（C1–C3 是关联，C4 才接近因果）。界面上必须永久标注这个区别
- **6 周以上的滞后效应** —— 样本不够
- **声量对复购的影响** —— 需要多年数据
- **任何未控制变量的效应** —— 缺货、竞品价格战、平台算法变更

**一条永久纪律**：把关联说成因果，是这个品类最常见也最贵的错误。

### 8.2 八层的数据流与输出契约

每层不只说做什么，还要说**它的输出契约**——上一层变了，下一层怎么知道。

| 层 | 输入 | 输出 | **失败模式** |
|---|---|---|---|
| 采集 | Apify actors | 原始载荷 + 首次见到时间 + 抓取时点 | 时滞偏差、跨源重复、删帖缺失 |
| 存储 | 原始载荷 | 四类归属命名空间 + 增量/全量分离 | 快照被当成历史 |
| 打标 | 文本/图/视频 | 标签 + 版本 + 置信度 | 标签改版使历史不可比 |
| 指标 | 标注记录 + ERP | 三族指标 + 口径版本 | 分母定义漂移 |
| 分析 | 指标 + 控制变量 | C1–C4 + 区间 | 伪相关、缺货反向、同期群混同 |
| 呈现 | 分析结果 | 可下钻的聚合 | 聚合后丢明细 |
| 结论 | 分析 + 血缘 | 结论卡（含证伪条件） | 结论无法被推翻 |
| 报告 | 结论卡 | 主动推送 + 证伪检查结果 | 变成又一个 dashboard |

**输出契约的写法**：每层输出带 `schema_version` + `produced_at` + `upstream_versions`。
下游读到陌生的上游版本时**必须报警而不是猜**。这是本仓库「两处各写一遍」教训的直接应用。

### 8.3 三根柱子穿进八层（每层各担一份具体责任）

不是三章，是一张责任矩阵——这样才不会变成三个写在文档里、没人执行的口号。

| | 口径 | 质量三态 | 血缘 |
|---|---|---|---|
| 采集 | 什么算「一条内容」 | 今天这个源抓到了吗 | 记录 → Apify 任务 id |
| 存储 | 归属命名空间定义 | 重复率、缺失率 | 记录 → 原始载荷 |
| 打标 | 标签体系版本 | 金标准集准确率 | 标注 → 模型版本 + 阈值 |
| 指标 | **指标卡八项字段** | 分母异常检测 | 指标 → 标注集合 |
| 分析 | 模型设定版本 | 有效样本量是否达标 | 结论 → 模型 + 数据切片 |
| 呈现 | 数字旁显示口径版本 | 三态可见 | 一键下钻 |
| 结论 | 范围里写明口径版本 | 依据的样本量达标吗 | 依据 → 全链路 |
| 报告 | 证伪条件可执行 | 每周跑证伪检查 | 结论卡 → 血缘链 |

### 8.4 实施顺序：自底向上建，但每一步都可交付

**第一步不做全栈。** 用最小数据跑通一次端到端，同时验证两件事：识别策略和数据形状。

**第 0 步（1 天）：§七 的相关性检查。** 不过就停，别往下走。

**第 1 步（2 周）：一条最小端到端。** 2 个区域 × 12 周，只用 Amazon 评论增速（唯一能重建历史的源）+ ERP GMV。
不做打标、不做呈现、不做报告。**产出一个数**：这 12 周里两区域的弹性差，带区间。
它验证的是「这条路走得通吗」，不是「结论对不对」。

**第 2 步：补控制变量。** 促销、价格、**库存**（缺货不补，结论不可用）。
这时才值得扩到 52 周。**如果这一步的结论与第 1 步方向相反，说明控制变量里有主导因素**，值得单独研究。

**第 3 步：补声量源与打标。** 加 TikTok/IG，上标签体系与金标准集。
**这一步才需要区域归属**——而 Amazon 评论本身就带市场归属，所以前两步不需要它。

**第 4 步：结论卡与报告。** 但**证伪条件从第一张卡就要写**，不是最后补。

**第 5 步：呈现与下钻。** 放最后，因为前面每一步都能用表格交付。

**这个顺序的关键**：每一步都产出一个**可以被证伪的数**，而不是一个「已经搭好的层」。
第 1 步结束时就可能发现「识别不成立」——那时只损失两周，不是三个月。

### 8.5 这套方案自己怎么被证伪

方案本身也要有证伪条件。以下任一出现，说明方案错了：

1. **§七 相关性 > 0.8** → 识别策略不成立，整个面板方案作废
2. **第 2 步加入控制变量后，C1 的排序完全反转** → 说明主效应不是声量，是某个控制变量
3. **C1 在各区域上的系数符号不一致** → 没有统一机制，面板假设错误
4. **弹性区间跨过 0** → 没有可识别效应，产品不该给这个结论
5. **打标准确率（金标准集）< 0.7** → 情感维度不可用，A2+/A2− 退化为 A1
6. **区域归属覆盖率 < 40%** → 分母不可用，回到品牌整体层面
7. **预算一年内只调整过一两次** → C4 无识别力，降级为描述性对比

**第 4 条最容易被忽略也最重要**：一个跨过 0 的区间看起来像「有这个效应」，实际上什么都没说。
产品必须把这种结论标为「无结论」，而不是「效应弱」。

## 九、这份方案没解决的问题（诚实清单）

1. **全球效应测不了** —— 周固定效应的代价，是设计约束
2. **1 年窗口对 C2/C4 偏紧** —— 如果第二年数据更好，建议延长后再下结论
3. **删帖缺失无法修复** —— 只能记录缺失率，不能补
4. **账号粉丝地理结构未做** —— 深方案的一部分，等一期结论不稳再上
5. **跨源去重的阈值未定** —— 需要拿真实数据标定，不能拍脑袋
6. **情感打标在母婴黑话上的准确率未知** —— 金标准集建起来才知道
