> **极简导航（按生命周期排序）**：你只需要按当前所处的步骤，直接复制对应的「一句话口令」给 Claude。

## 一、速查地图（你现在在哪一步？）

```text
[1. 需求]  →  [2. 设计]  →  [3. 开发]  →  [4. 验收(硬门)]  →  [5. 交付]  →  [6. 运营]  →  [7. 迭代]
   │             │             │                │               │             │             │
anb-idea     anb-design   anb-runnable    anb-judgeable    anb-shipable  anb-observable  anb-reusable
```

## 二、ANB 核心七阶段 + 检查器（必读主力）

### 1. 阶段路由与主干
* **`anb`**
  * **什么时候用**：不知道下一步做什么、或者感觉哪里不对劲时。
  * **一句话口令**：`用 anb 定位：我现在卡在 ___，下一步该调哪个 skill？`
* **`anb-idea`**（阶段一：需求）
  * **什么时候用**：把一句话想法定型为 5 句意图，包含必须可测量的「否定条件/停止信号」。
  * **一句话口令**：`用 anb-idea 帮我理清这个想法，必须包含什么情况下说明不该做。`
* **`anb-design`**（阶段二：设计）
  * **什么时候用**：回答设计四问（流程形状、拒绝清单、动作权限、工具交接契约）。
  * **一句话口令**：`用 anb-design 输出四问设计记录，拒绝清单必须写成输入到动作的映射。`
* **`anb-runnable`**（阶段三：开发）
  * **什么时候用**：只做一条最窄的真实贯通链路，杜绝任何假数据和写死特判。
  * **一句话口令**：`用 anb-runnable 实现一条最窄链路：真实输入进，真实结果出，不要架子。`
* **`anb-judgeable`**（阶段四：验收 · 唯一硬门）
  * **什么时候用**：建立必须能失败的自动化检查标准。本门不过，禁止进入交付。
  * **一句话口令**：`用 anb-judgeable 建立验收检查：把设计阶段的拒绝清单变成自动化测试。`
* **`anb-shipable`**（阶段五：交付）
  * **什么时候用**：换一台设备或让陌生人试用，确保离开你也能跑通。
  * **一句话口令**：`用 anb-shipable 做交付检查：测算配额墙、清点环境变量与外部依赖。`
* **`anb-observable`**（阶段六：运营）
  * **什么时候用**：上线后建立三项最核心技术指标（跑了几次、花了多少钱、为什么失败）。
  * **一句话口令**：`用 anb-observable 补齐技术观测：确保打开就能看到调用次数与失败归因。`
* **`anb-reusable`**（阶段七：迭代）
  * **什么时候用**：从真实运行数据决定改什么，只沉淀经过 2 次以上验证的通用模块。
  * **一句话口令**：`用 anb-reusable 评估沉淀：哪些代码形状固定可以抽成模板？`
* **`anb-manage`**（全周期管理）
  * **什么时候用**：查询项目真实状态、创建票据、归档证据或记录事故。
  * **一句话口令**：`用 anb-manage 查看项目真实状态，并把刚才的测试输出存为证据。`

### 2. 验收阶段的 7 个硬核检查器（故意弄坏）
* **`anb-check-break`**：故意改错一行代码或输入，亲眼验证检查必须变红。口令：`用 anb-check-break 故意弄坏测试，证明它不是永远报绿。`
* **`anb-check-offline`**：断网或输入错误密钥，验证报错是明确的「无法判断」而不是静默绿。
* **`anb-check-readback`**：逐条念出检查结果，抓出被隐藏的「跳过（Skip）」项。
* **`anb-check-output`**：人工抽检 3 个真实复杂样本，验证产出是否真的可用。
* **`anb-check-reconcile`**：计算器对账（成功数 + 失败各分类数 是否严格等于总数）。
* **`anb-check-count`**：用第二种独立方式重新统计指标，防止统计代码自嗨。
* **`anb-check-otherdevice`**：在手机或新机器上打开部署链接，验证零配置可用性。

### 3. 数据产品专属 3 技能（8层+3柱）
* **`anb-data-metric`**：指标层契约，定义公式、时点与版本，判据是换人也能算出同一个数。
* **`anb-data-label`**：打标层契约，定义标签置信度、版本映射与标注一致性 Kappa 门槛。
* **`anb-data-conclude`**：结论层契约，规范四级结论卡（C1–C4），必须自带可执行证伪条件。

## 三、工程开发与实现 Skill（写代码主力）

* **`agent-delivery-router`**：任务刚开始时，快速判定走哪条车道（故障/探索/能力/快速）。
* **`spec-driven-development`**：先写出完整规格（目标、测试、约束），经批准后再动手。
* **`to-spec`**：把刚刚聊透的上下文直接固化为规格草案。
* **`writing-plans`**：将规格拆解为带逐步测试命令的详细实施计划。
* **`to-tickets`**：把计划拆分成带阻塞依赖关系的纵向切片任务票。
* **`tdd`**：严格的测试驱动开发（先写红测试 -> 写最小实现 -> 变绿重构）。
* **`implement`**：单票实现标准流水线（读票 -> TDD -> 类型检查 -> 审查 -> 提交）。
* **`implement-spec`**：针对多张票的大规格，按依赖前沿逐票集成并统一审查。
* **`ponytail`**：克制开发模式，只写解决问题所需的最小代码，绝不添加多余抽象。
* **`karpathy-guidelines`**：减少假设、小步修改、保证每一步都有可验证标准。
* **`using-git-worktrees`**：创建独立的 git worktree 隔离工作区，确保基线干净。
* **`subagent-driven-development`**：多子代理并行编排开发，每票独立审查。
* **`todo-ledger`**：跨会话维护 Now / Next / Done 真实账本。
* **`handoff`**：在会话结束时输出结构化交接文档，便于下次无缝接力。

## 四、审查、评测与排障 Skill（守门主力）

* **`llm-evaluation`**：构建模型评测集（黄金数据集、确定性规则、裁判偏差控制）。
* **`code-review`**：从「代码规范（Standards）」与「业务规格（Spec）」双轴做严格代码审查。
* **`ponytail-review`**：审查代码改动中「哪一行其实根本不需要写」，消除代码臃肿。
* **`security-review`**：排查高置信度安全漏洞（注入、越权、密钥泄露、租户隔离）。
* **`diagnosing-bugs`**：排障循环：先建立一个可稳定变红的复现测试，再探究根因并修复。
* **`verification-before-completion`**：任何宣称“已完成/已修复”之前，必须跑命令贴出真凭实据。
* **`test-suite-health`**：清理脆化、运行过慢或无意义的重复测试。

## 五、架构、设计与调研 Skill（思考主力）

* **`interview-me`**：通过一问一答采访提取你脑中的真实意图与成功标准。
* **`grilling` / `grill-me`**：无情拷问你的设计方案，找出边界漏洞和模糊假设。
* **`grill-with-docs`**：在拷问方案的同时，同步沉淀术语表（Glossary）与 ADR 架构决策。
* **`architecture-decision-records`**：记录重大技术选型，必须写明放弃的方案与代价。
* **`domain-modeling`**：锁定核心领域名词定义与反例，杜绝一词多义。
* **`codebase-design`**：分析模块深浅、接口正交性与解耦缝隙（Seam）。
* **`api-and-interface-design`**：契约优先设计 API，明确错误语义、分页与幂等机制。
* **`database-schema-designer`**：设计规范化表结构、约束、索引与可回滚迁移脚本。
* **`auth-implementation-patterns`**：设计认证授权（Session/JWT/OAuth2/RBAC/多租户）。
* **`research`**：委派后台深入调研一手文档与源码，产出带出处的调研笔记。
* **`improve-codebase-architecture`**：全仓扫描架构深化机会并输出可视化分析报告。

## 六、部署、运营与交付 Skill

* **`deploy-checklist`**：发布前核对 CI、迁移、配置与 15 分钟回滚触发指标。
* **`deployment-patterns`**：容器化 Dockerfile、CI/CD 阶段与发布策略。
* **`observability-and-instrumentation`**：从告警问题倒推结构化日志、指标度量与链路追踪。
* **`instrument-product-analytics`**：定义产品埋点事件、用户旅程与漏斗分析。
* **`artifact-registry`**：为所有有持续维护成本的产物登记 Owner 与过期销毁时间。
* **`repo-gc`**：安全清理仓库中的僵尸代码、过期脚本与废弃依赖。
* **`tech-debt`**：建立打分量化的技术债务登记簿并制定偿还计划。
* **`pr`**：生成包含前后对比证据和合并风险评估的高质量 PR 文案。
* **`milestone-report`**：生成单 HTML 页面的里程碑汇报，结论与证据先行。

## 七、界面、文档与特种 Skill

* **`ui-ux-pro-max`**：UI/UX 设计系统、组件库规范、响应式与无障碍支持。
* **`impeccable`**：界面设计评审、视觉细节打磨、交互微动效优化。
* **`taste-skill`**：反模板化、反 AI 廉价感的前端视觉与排版指导。
* **`diagram-design` / `archify`**：生成架构图、时序图、流程图或可交互 HTML 架构看板。
* **`agent-browser`**：控制真实浏览器进行点击、表单填写、截屏与数据抓取。
* **`rag-implementation`**：设计知识库 RAG（切块、混合检索、重排与真实引用）。
* **`docx` / `pdf` / `xlsx` / `pptx`**：专业 Office 与 PDF 文档生成、提取与排版。
* **`i-have-adhd`**：切换为针对 ADHD 的极简结构化输出模式（行动先行、突出重点）。
* **`humanizer`**：润色 AI 生成的文本，去除 AI 味和套话，回归自然人声。
