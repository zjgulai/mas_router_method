# Main Agent 独立盲评（30 条）

**目的**：用第二双眼睛找“自审全绿”之外的问题，不把 eval 通过率当成可用性。
**样本**：从 150 条 eval 中分层抽 30 条（in_scope 10 / needs_context 10 / out_of_scope 10），生成 B01–B30；盲文件只含问题与回答，不含预期类别、节点、来源。
**评审**：每轮用一个新的、无仓库上下文的 AI 评审，只读盲文件；按“直接回答 / 可执行 / 证据边界”三项 0–2 分判 `usable` 或 `needs_improvement`。
**复现**：

```bash
python3 scripts/build-blind-review.py \
  --out /tmp/main-blind.json \
  --key .data/blind-key.json \
  --seed 20261029
```

**边界**：这是 AI 评审，不是人类盲评。它能发现“模板化、答非所问、引用不相关”，但不能替代真实用户验收；最终仍需第二个人类抽 30 条盲评。

## 结果

| 轮次 | 改动 | needs_improvement | 主要分歧 |
|---|---|---:|---|
| R1 | 初始版本 | 9 / 30 | 通用上下文模板、答非所问、指标版本、万能模板、VOC/标签覆盖、PR 文章 |
| R2 | 第一轮上下文/直接回答修复 | 4 / 30 | 权限/文件/代码审查拒答、进度工作总结 |
| R3 | 增加具体拒答与 PR/进度 play | 6 / 30 | 统计噪声；同一样本不同评审关注点不同，不能读成回归 |
| R4 | 上下文澄清改为“给步骤”，去掉错节点框架 | 1 / 30 | 进度问题仍套用别的汇报示例 |
| R5 | 进度澄清提取用户提到的条目 | 1 / 30 | PR 文章仍只给流程，未推进生成 |
| R6 | 复核最终版本 | 1 / 30 | 同上：PR 文章缺实际话题/claims，无法直接出稿 |
| R7 | B29 单条复评（补“待填大纲”后） | 0 / 1 | 通过：明确要三项输入，并给出可直接填的大纲 |

**最终一致率**：内部自审 30/30 可用；盲评 30/30 可用。R6 唯一未过的 B29（PR 文章生成）在补齐“三项输入 + 标【待填】的大纲”后单条复评通过；其余 29 条沿用 R6 结果，没有再做一次全量 30 条。

> 评审有噪声：同一批回答在 R2 与 R3 之间从 4 变 6，主要来自评审关注点不同，不代表改动让回答变差。看趋势和重复出现的主题，不看单轮数字。

## 已修复的主题

| 主题 | 盲评原话（归纳） | 修复 |
|---|---|---|
| 通用上下文模板 | “问‘它和那个哪个好’，却让用户提供文档/表/环境” | `clarifyFor()` 按问题类型分支：两个候选、上次消息、指标定义、agent 复现输入、进度条目、最终文档 |
| 错节点框架 | “已经要求补充上下文，却又附上结论卡模板” | 歧义问题不再输出猜测节点的框架、依据、下一步、相关节点；改为“尚未定位”+ 收集上下文的步骤 |
| 指标版本 | “问 A/B 能否相减，回答复述指标卡八项” | 新增 `metric-version-subtract` play：不能直接相减，并排展示或映射重算 |
| 万能模板 | “适合所有行业的指标模板被整体拒答” | 从 `UNSAFE_PATTERNS` 移除；新增 `no-universal-template`，拒绝伪前提但给指标卡八项 + 按行业补全流程；数据集改为 in_scope |
| VOC 到选题 | “只讲采集时点，没讲洞察和选题” | 新增 `voc-to-topic`：接入 → 洞察 → 选题三层，各自验收 |
| 标签覆盖 | “只讲版本规则，没讲非产品讨论占一半” | 新增 `taxonomy-coverage`：加平级分支、统计覆盖率、金标准校验 |
| 进度百分比 | “只讲百分比不是进度，没提用户说的两个条目” | 进度澄清提取问题里的条目名，逐项对应 G1–G5；MCP/重构单独走变更风险分支 |
| 拒答不具体 | “删群/密钥/手机号/文件/会议都回同一张菜单” | `refusalFor()` 按红线给具体边界：凭据、破坏性操作、隐私、权限、文件、日历、代码审查、业务数据 |
| PR 文章 | “只给流程，没有要求话题/claims 或出大纲” | 新增 `pr-article-playbook`：claims 表、风险/禁用表达、文章结构、人工复核；仍需用户给素材 |

## 仍未解决

- **证据相关性**：部分回答的 `【依据】` 仍会引用弱相关文档（盲评 B01/B14/B27 提到）。已把节点 `sources` 优先注入检索，并让 direct play 只列与问题词重叠的来源；代码文件/短文档的片段选择还需继续调。
- **人类盲评缺失**：当前评审是 AI，且每轮是新会话；真实用户是否觉得“可用”仍未验证。人类盲评包已生成：`docs/evals/main-agent-human-review-packet.md`。
