## 做什么

让矩阵显示「哪一格有人做」，而不只是「哪一格有契约」。

1. 工单 frontmatter 加 `cells:`，声明它覆盖矩阵的哪几格
2. `scripts/ticket-cells.mjs`：从 `work/tickets/<state>/` 读状态，与矩阵 join
3. 状态映射：`open`/`in-progress` → pending，`awaiting-verification` → claimed，
   `done` → landed，`abandoned` → stopped
4. 一个格子被多张票认领时取**最弱**的那张
5. 「没票」分两种：**缺口**（正在进行的阶段，该有票却没有）与**未到**（产品没上线，
   运营/迭代/管理三层的票要等前面走完）
6. 页面加「缺口 / 未到」两个筛选，缺口格子画红框

## 完成判据

- [x] 工单加 `cells:` 字段，通配符只扩展到**存在**的格子
- [x] 显式写出的格子即使不存在也保留，好让拼错能被报出来
- [x] `matrix-check` 交叉校验：票声称的格子必须真实存在
- [x] `awaiting-verification` 不提升为 verified
- [x] 多票取最弱；abandoned 不让格子永远半成品

## 这一接上就发现的

**打标层整列没有票。** 设计、开发、验收三格全空。三条链（A 采集存储、B 指标分析、
C 结论报告）恰好都绕过了打标层，而产品的情感维度 A2+/A2− 依赖它。这是方法层面的缺口，
不是进度问题。

**通配符造假覆盖。** `*·采集` 让 T-006 看起来覆盖管理·采集；实际它只做了
设计/开发/验收三格。已改成显式六格。
