# D-002 客服回复草稿

## 一、流程形状

固定步骤：读消息 → 找出诉求 → 查政策（必要时查订单）→ 起草 → 对照政策自检 → 标注依据 → 输出。

需要临场判断的地方：① 这条消息触到了哪条政策条款 ② 草稿有没有越线。

**判断点：2 处。**

**多诉求时的规则**：不做取舍，逐条按政策回应，能明确回答的在前。
「不做取舍」约束的是**排序与覆盖**——每条诉求都要有回应，不许挑一条答。
它**不约束存活**：某一条触发升级，不影响其他条照常回应（见下）。

**升级是逐条的，不是整封的。**
- 某条诉求触发升级 → 只有那一条不出草稿，其他条正常回。
- **所有**诉求都被硬升级 → 整封成为升级单，不含任何面向买家的文本。

（这条是实测修出来的。原写法是「任何一条落在转人集合里 → 整封转人」，
那会让一封「要退款 + 宝宝起红疹」的消息在退款那条上一个字都不答——而那恰恰是客服最需要的答案。）

**判断点①怎么算**：诉求的输入必须是**买家原文的逐字片段**，不许先概括再检索。
先概括会把「能防猝死吗」变成「安全性质询」，然后命中一条看起来完全正常的条款——
日志里每一行都正常，那正是失败图鉴第二类。

**重议条件**：出现一条真实买家消息，两个诉求无法逐条按政策回应
（例如两条政策对同一件事给出相反答案）→ 那一次就是第三处判断点，改成 3 并重画。

## 二、拒绝清单

**对照物**：`docs/policy/after-sales-replies.md`（T-005 从散在三处的来源拢成）。
每一行都是「具体买家消息 → 必须改做什么」，所以验证阶段能把每一行变成一条检查。

**十一行。**

- 「用了之后宝宝脸上起了红疹」→ **软升级**：可以回。表达关切 + **照抄**成分信息（不加解释）+
  建议停用并咨询儿科医生；整封标记为需人跟进。
- 「这个睡袋能防止宝宝猝死吗？」（及窒息、发育、疗效类提问）→ **硬升级**：
  **绝对不答**，本条不出草稿，且不得提及任何具体疾病名词。
- 「我家宝宝 3 个月，这个能用吗？」→ 陈述适用月龄 + 明说「替家长判断超出范围」+
  建议咨询儿科医生。可以补一句「再大一点就能用了」。**不升级。**
- 「已经两周了还没到，我要全额退款」→ 不直接答应。陈述物流实际状态 + 说明符合哪条政策 +
  **「你可以申请退款」**。（见第 3 块：草稿不得声称已经提交申请。）
- 「收到了，但我不满意，要退」→ 按政策说明退货条件（时限、商品状态、运费由谁承担）。
  不给优惠券替代安抚。
- 要求**超出政策**的补偿（券、赠品、赔偿）→ 硬升级，不讨价还价。
  政策内的**正常**补偿（不是交换条件）可以给。
- 「退货的运费你们出吗？」→ **质量问题我方承担，其他情况买家承担。** 不随口承诺。
- 「关税是谁付？」→ 买家承担，下单页已注明。**不得承诺我方承担。**
- 「我下周五要用，能到吗？」→ **不承诺任何时效**，只陈述已记录的物流状态。
  不给「一般 7–14 天」这类经验值——在纠纷里那个数字就是一句承诺。
- **以「不投诉 / 不公开 / 不改评价」为条件的补偿 → 一律不接。**
  我方不主动提，买家主动提也不接。（这一行覆盖第 6 行之外的交换行为；
  「不投诉」和「改评价」是同一种交换，不分开处理。）
- 「你们东西真好用」→ 可以邀请评价，**但不得以任何补偿为条件**。

**第 1、2、3 行的状态是「用户确认，未经实例验证」。** 用户确认建议经得起实际发生的事例，
但具体发生过几次、当时怎么处理的没有拿到。**这是「无法判断」，不是「通过」。**

## 三、动作权限

| 动作 | 档 | 理由 |
|---|---|---|
| 读买家消息、读政策、读订单与物流状态 | 可撤销 | 只读，错了没有任何后果 |
| 起草回复 | 可撤销 | 草稿不出门，删掉即可 |
| 标注「这一句依据哪条政策」 | 可撤销 | 同上 |
| 提交退款申请 | **不在范围** | 这一步由人做 |
| 发送给买家 | **不在范围** | 这一步由人做 |

**「必须问人」那一档是空的。** 这是刻意的，也是这个设计安全的原因：产品自己碰不到不可撤销的动作。

**「转人」和「必须问人」不是一回事，这两个词在本文件里不混用：**
- **必须问人** = 阻塞。行动前必须拿到人的批准。本产品没有这类动作——**因为它不行动**。
- **转人** = 标记。流程照常跑完，然后盖一个「人必须接手」的章。

正因为它从不行动，「转人」才够用；也正因为如此，**草稿里不得出现任何「已经做了」的说法**：
可以说「你可以申请退款」，不能出现「我已为你提交」。前者是陈述，后者是它冒充自己做了一个动作。

**一条不属于任何档、但决定上表成不成立的前提：**

> 草稿必须以「逐句标注依据」的形式呈现，而不是一整段给完。
> 否则客服会看一遍、觉得通顺、直接发出——**那道闸门就是纸做的**。

**重议条件**：若将来接上「自动发送」或「真的提交退款申请」，这一块必须整块重画——
那会新增第一个不可撤销动作，而上面整段安全论证随之失效。

## 四、交接契约

三个工具，每个三行。第二行（什么时候别用）是所有人都会省掉的那一行。

**`查政策条款`**
- 做什么：按买家诉求找出相关条款。**输入必须是买家原文的逐字片段。**
- **什么时候别用**：不要用它回答医疗与安全类**提问**——那类硬升级。检索不到对应条款时就停，
  **不要返回一条最接近的**。
- 失败返回：「这份政策没有覆盖这一条」→ 本条硬升级。

**`查订单与物流状态`**
- 做什么：按订单号取出当前状态。
- **什么时候别用**：订单号不明确时不要猜（可能没有、可能有好几个）。不要用订单状态推断
  「所以应该退款」——那是政策的事。
- 失败返回：「订单号 X 查不到，请确认单号」，明确不要用同一个号重试。

**`标注依据`**
- 做什么：给草稿的每一句标出它依据的政策条款。
- **判定必须是机械的**：句子的依据必须落在**本次检索到的条款集合**内。
  **不做第二次检索**——第二次检索会让「这句有没有依据」变成第三个判断点。
- **什么时候别用**：某一句找不到依据时，不要标一条最接近的。给草稿「尽力」配一条依据，
  会让一句没有依据的话看起来有依据。
- 失败返回：明确标「这句没有依据」，并把**整封**标记为需要人判断。
  理由：**半封可信的草稿比一整封不可信的更危险**——人会挑着信。

## 五、产出形态

这条流程有五种结局，每种结局下人拿到手的东西：

**1. 走通** → 一张**逐句列表**，每句挂它的依据条款。状态「**可发候选**」。
没有「整段纯文本」的默认视图——可复制的那一块由逐句列表**机械拼出**，不由模型另写一遍。

**2. 某句越线** → 同一张逐句列表，状态「**需人判断**」。越线的那句标出**越了哪一条**，
并写明它违反的是政策里的哪个动作（不是「读起来不对」）。**不自动改写**——
自动改写会把越线检测器变成越线消除器。

**3. 某句没有依据** → 内容保留，状态「**需人判断**」，那一句显式标「这句没有依据」。

**4. 某条诉求硬升级** → 那张诉求条目下**不出草稿**，写明触发了哪条政策。
**其余诉求照常回应**（升级是逐条的）。只有当所有诉求都被硬升级时，才变成 ↓

**5. 整封升级** → **不产出任何面向买家的文本。** 只出一张升级单：
买家原文（逐字回显，供人判断）、触发的条款、以及「由人工按政策答复」。
原文回显属于输入记录，不属于草稿块。
