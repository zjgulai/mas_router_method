# D-001 从爆款参考视频生成一份品牌可拍的配方

四问的记录。答完就落一行，不是写完再落。这份记录本身就是这套方法的样本：
它用 `anb-design` 问出来，没有用架构文档的方式写。

## 一、流程形状

**固定步骤**（每次一样，顺序不变）：

1. `get_brand_profile` 读品牌画像与护栏。
2. 用户贴链接 → `save_reference_video` 存下参考。
3. `analyze_reference_video` 出结构化拆解（hook 模式、beat 骨架、镜头、口播、音频归属、可迁移度）。
4. 写配方 → `save_recipe_draft` 落草稿，等人工审。

**需要临场判断的步骤**：

- 判断这个参考的「可迁移度」——哪些元素是别人的资产，必须进 exclusions。
- 判断脚本里每句事实性宣称能不能被品牌证明（`claimsSubstantiated`）。
- 判断画面用哪个 beat 承接，才能让拍摄者在现场真的拍得出来。

**判断点：3 处。**

这个数是刻意的。三处以上说明我在让模型替我想清楚产品该怎么做；
零到一处说明这其实是个管线，不需要模型自己决定顺序，一次模型调用套在脚本里更便宜也更好查。
现在是三处，所以 agent 是对的形态——但这个数要在拿到真实运行数据后重新数一遍，
如果实际只有一处真需要判断，就该往管线退。

## 二、拒绝清单

- 要求写「治愈痘痘」类医疗宣称 → 必须拒绝，并改成外观表述，附品牌要求的免责声明。
- 要求照搬参考视频的原话或原片 → 必须拒绝复用文字与素材，只在 exclusions 里记下放弃了什么。
- 要求生成「减肥前后对比」→ 属于 `prohibitedTopics`，直接拒绝并说明这是品牌禁区。
- 要求把配方标成「已审核」→ 必须拒绝。只有人能审核，工具不接受这个状态。
- 用户要求分析一个已经存过的 reference 第二次 → 不拒绝，但要说清这会再花一次钱、返回同样的结构。

## 三、动作权限

| 动作 | 档 | 理由 |
|---|---|---|
| 读品牌画像、列参考、读拆解 | 可撤销 | 只读，错了没有任何后果 |
| 存参考视频 | 可撤销 | 记一条记录，删掉即可 |
| 分析参考视频 | **有额度** | 不可见但花钱。同一个 reference 重复分析会重复计费——成本在运行账本里，不在用户眼前 |
| 存配方草稿 | 可撤销 | 草稿不是发布，人工审之前不出门 |

**必须问人的：** 无。这个产品到目前为止没有任何不可撤销的动作——它不发布、不发送、不付款。
这是它现在能跑得比较快的原因，也是它上线前必须重新问一遍第四问的原因：
一旦接上「自动发布到品牌账号」，就多出一档不可撤销，那时必须有额度与人工确认。

## 四、交接契约

五个工具，每个三行（做什么 / 什么时候别用 / 失败返回什么）：

- **`get_brand_profile`** — 读当前品牌的画像与护栏。/ 别用：无例外，任何后续动作前都必须先调。/ 失败：`No brand profile found for <id>`，不重试。
- **`save_reference_video`** — 存一个参考视频，不分析。/ 别用：还没确认链接列表时不要逐个存，先跟用户核对。/ 失败：URL 非法，换链接。
- **`list_reference_videos`** — 列出已存的参考及其是否已分析。/ 别用：不要用它代替 `get_brand_profile` 来做品牌判断。/ 失败：返回空列表，不报错。
- **`analyze_reference_video`** — 出结构化拆解并落盘。/ 别用：没有先 `save_reference_video` 不要调；不要用不存在的 id 试探。/ 失败：id 不存在时明确说「调 list_reference_videos 看有效 id，不要用同一个 id 重试」——这句让循环自己结束。
- **`save_recipe_draft`** — 落草稿交人工审。/ 别用：`analyze_reference_video` 还没返回时不要调（不许发明拆解）；不要标审核状态。/ 失败：schema 校验失败，说明哪个字段，改字段而不是重试同一份。

## 五、什么情况说明这个设计错了

- 真实运行里三处判断点合并成一处（模型从不改变顺序）→ 应该退回管线，去掉 agent 的自主性，省下的钱和时间可以用来做更多次分析。
- 模型在 `exclusions` 里长期写空 → 说明「可迁移度」这处判断没有真的发生，第一问的判断点少算了一处。
- 有人要求「直接发出去」超过两次 → 第四问缺一档，权限表要重画。
