# D-002 客服回复草稿

## 一、流程形状

固定步骤：读消息 → 找出诉求 → 查政策（必要时查订单）→ 起草 → 对照政策自检 → 输出。

需要临场判断的地方：① 这条消息触到了哪条政策条款 ② 草稿有没有越线。

**判断点：2 处。**

**多诉求时怎么办（这一处算不算第 3 个判断点，我们没谈拢）：**

规则写下来是——**不做取舍，逐条按政策回应**，能明确回答的在前；若其中任何一条落在
「必须转人」集合里（健康、安全、医疗宣称），整封转人。

这条规则在构造出的反例上都站住了，所以记为规则而非判断点。但用户坚持它是判断点，
而我在方法里找不到裁决机制。**按方法已有的「重议条件」机制处理：**

- **什么情况说明这个数错了**：出现一条真实买家消息，两个诉求无法逐条按政策回应
  （例如两条政策对同一件事给出相反答案）。那一次就是第三处判断点，回来改成 3 并重画。

## 二、拒绝清单

**状态：被 T-005 阻塞。** 现状是政策「存在但散在几处」（平台后台模板 + 内部消息 +
主管口头补充），所以这一块要等政策拢成一份才能写完。

已经确认写在政策里的三条：

- 「我家宝宝 3 个月，这个能用吗？」（产品标注 6 个月以上）→ 不能答「可以」，也不能含糊。
  必须陈述适用月龄，并明确「替家长判断适不适合你的孩子超出范围」，建议咨询儿科医生。
- 「东西一直没到，我要全额退款」→ 不能直接答应。先陈述物流记录的实际状态，说明符合哪条政策，
  用「我可以为你发起退款申请」——申请与答应不是一回事。
- 买家给了差评并暗示可以改 → 不能提出任何以改评价为条件的补偿。违反平台规则，且会被截图。

**待 T-005 确认的三条**（用户说这三条现在一律问主管，所以最可能是没写下来的）：

- 宝宝使用后起红疹等健康反应 → 预期是「完全不能回，原样转人」，连安慰性措辞也算越线
- 涉及猝死、窒息、发育的问题 → 预期是「绝对不能回答」，母婴品类里唯一一条答错的代价是人身伤害
- 跨境退货运费谁承担 → 预期是「按政策实际条款答，政策没写清的转人」

## 三、动作权限

| 动作 | 档 | 理由 |
|---|---|---|
| 读买家消息、读政策、读订单与物流状态 | 可撤销 | 只读，错了没有任何后果 |
| 起草回复 | 可撤销 | 草稿不出门，删掉即可 |
| 标注「这一句依据哪条政策」 | 可撤销 | 同上 |
| 发送给买家 | 不在范围 | 这一步由人做 |

**「必须问人」那一档是空的。** 这是刻意的，也是这个设计安全的原因：产品自己碰不到不可撤销的动作。

**一条不属于任何档、但决定上表成不成立的前提：**

> 草稿必须以「逐句标注依据」的形式呈现，而不是一整段给完。
> 否则客服专员会看一遍、觉得通顺、直接发出——**那道闸门就是纸做的**，
> 上面所有的「可撤销」随之失去意义。

这条也解释了这个设计为什么选 (c) 而非 (a)：逐句标注不只是安全感，它是让闸门变成真的东西。

**重议条件**：若将来接上「自动发送」，这一块必须整块重画。

## 四、交接契约

三个工具，每个三行。第二行（什么时候别用）是所有人都会省掉的那一行，而 agent 产品最常见的
失败不是工具坏了，是一个正确的工具被用在了不该用的地方——日志里每一行都正常。

**`查政策条款`**
- 做什么：按买家消息里的诉求，找出相关的政策条款。
- **什么时候别用**：不要用它回答健康、安全、医疗类问题——那类必须转人。检索不到对应条款时
  就停，**不要返回一条最接近的**。
- 失败返回：「这份政策没有覆盖这一条」。**重点不是报错，是不要「尽力而为」**：检索天然会返回
  最像的那一条，而在政策场景里，「最像的」恰恰是那个看起来完全正常的错误答案。

**`查订单与物流状态`**
- 做什么：按订单号取出当前状态。
- **什么时候别用**：消息里订单号不明确时不要猜（可能没有、可能有好几个）。也不要用订单状态
  去推断「所以应该退款」——那是政策的事，不是物流状态能推出来的。
- 失败返回：「订单号 X 查不到，请确认单号」，并明确「不要用同一个号重试」。

**`标注依据`**
- 做什么：给草稿的每一句标出它依据的政策条款。
- **什么时候别用**：某一句找不到依据时，**不要标一条最接近的**。这一行正是健康类拒绝的来源：
  草稿里冒出一句没有依据的话，这个工具「尽力」给它配一条，它就会看起来有依据。
- 失败返回：明确标「这句没有依据」，并把**整封**标记为需要人判断，而不是照常输出。
  理由：需求阶段的核心是「发出之前知道有没有越线」，而**半封可信的草稿比一整封不可信的更危险**
  ——人会挑着信。
