# 指标层：一个数字的定义

**开场先问：「这个数字如果错了，决策会怎么错？」**

答不出来，这个指标不该存在。答得出来但答案是「也没什么」，它不该进产品——它会让看板变厚，让真正重要的那个数被稀释。

指标层是数据产品里**唯一一个错了会静静传播的层**。采集坏了你会看到空值，打标坏了准确率会掉，分析坏了区间会变宽。指标错了什么都不会发生：数字照常出现，照常好看。

## 这一层最常见的一种死法

一个叫「声量效率」的指标：总 GMV ÷ 总提及量 × 平均互动率。

八项字段全填了，读起来专业，`metric-card.mjs` **全绿**——我实测过。

但它把三样不同粒度的东西混成了一个数：

- GMV 是**结果**，受价格、缺货、促销控制
- 提及量是**外部输入**，滞后 2–4 周
- 互动率是**内容的属性**，与销量没有已知方向

合起来之后，**任何一个变了它都动，而你看不出是哪一个**。区域 A 的「声量效率」比 B 高 30%，可能是 A 的声量更有效，可能是 B 上周缺货，也可能是 A 的帖子互动更高但没带来一单。

这不是算错，是**这个数没有含义**。而它看起来比任何单个指标都更像洞察。

所以这一层的第一条纪律：

> **一个指标只能包含同一层的量。分子和分母必须能被同一个原因解释。**

要做比值，分子分母得同层：GMV ÷ 订单数 = 客单价（同一层，可解释）。跨层相除得到的是「效率」，而效率只有在**两层之间的传导关系已经确立**之后才有意义——那是分析层的工作，不是指标层的。

## 六个问题，一张卡

一个问题一问，答案落进 `work/metrics/<slug>.md` 的一个 `## ` 块。八项里前三项是「它是什么」，后五项是「它什么时候骗你」。

先给推荐答案，让他同意或纠正，不要让他写散文。

| 问题 | 八项里的哪几项 | 什么时候问 |
| --- | --- | --- |
| 1. 它算的是哪一层的东西？ | 可执行定义 / 数据源 | 总是 |
| 2. 它的最小单位是什么？ | 粒度 / 单位 | 总是 |
| 3. 它什么时候是错的？ | 已知偏差 | 总是 |
| 4. 什么时候不许引用它？ | 什么时候不可用 | 总是 |
| 5. 它和谁一起看才有意义？ | （卡外的层间关系） | 有比值或复合指标时 |
| 6. 改口径的时候，旧数据怎么办？ | 口径版本 | 改一次问一次 |

## 问题 1 — 它算的是哪一层的东西？

**推荐答案先给：说出这个数由哪一层的记录加总而来，然后检查分子分母是不是同一层。**

八层里，一个指标只能落在其中一层：

| 层 | 这里的「一条」是什么 | 指标能问的问题 |
| --- | --- | --- |
| 采集 | 一条内容 | 抓到了多少 |
| 打标 | 一条标注 | 多少条被判为正面 |
| 指标 | 一个聚合值 | （指标层本身不再造新指标） |
| 分析 | 一次估计 | 弹性是多少 |

**可执行定义要写成别人能照着跑的样子。** 判据只有一条：换一个人，不问作者，能算出同一个数吗？

- 「按情感为正的内容加权求和」→ 不能。权重是多少？评论算几次？
- 「对 `sentiment = positive` 且 `confidence ≥ 0.6` 的记录，按 赞×1 + 评×3 + 转×5 求和，按 `first_seen_at` 归周」→ 能。

**这一项检查器抓不到。** `metric-card.mjs` 只判「写了没有、是不是空话、是不是把标题抄了一遍」。一条语法完美、数字全填、却混了三层的定义，它放行——上面那个「声量效率」就是现场证。**所以这一项必须人来判，而判据是上面那句「换一个人能不能算出同一个数」。**

## 问题 2 — 它的最小单位是什么？

粒度和单位是两件事，产品里混用它们是「两个报表对不上」的最常见原因。

**粒度**：聚合前的最小记录。写 `区域 × 周`，不写「按区域按周看」——后者没说去重后的还是去重前的。

**单位**：数的对象是什么。`条` 要说明含不含转发；`元` 要说明含不含税、含不含运、退货什么时候扣。跨境尤其：GMV 含税与否能让两个报表差 15%，而两个都叫 GMV。

**判据：拿一个极端值试。** 只有一个区域、只有一周时，这个指标还算得出来吗？算不出来说明粒度写错了（比如「按区域占比」在单区域时是 1，没有信息）。

## 问题 3 — 它什么时候是错的？

**这一项没有「无」。** 每个指标都在某种方式上是错的；说「无偏差」的，是把没想过当成了没有。

给三档让他挑，别说「想想有什么偏差」：

| 偏差的类型 | 例子 | 后果 |
| --- | --- | --- |
| **缺失导致系统性偏低** | 已删帖永久缺失，越早的周偏低越多 | 跨期比较时把「数据留存」读成「市场变冷」 |
| **口径导致不可比** | 点赞在多数平台可见，转发不总是 | 平台之间不能直接比大小 |
| **标定未完成** | 权重 1/3/5 是直觉值 | 数字绝对值无意义，只有同平台内趋势可用 |

**判据：这个偏差会让数字往哪个方向错？** 答不出方向，说明还不了解它，回去看数据。

## 问题 4 — 什么时候不许引用它？

这一项和上一项的区别，是这一项写的是**动作**，不是**性质**。

- 上一项：「权重未标定，所以绝对数无意义」——这是性质
- 这一项：「权重未标定时，不与上一期比较」——这是禁令

**判据：能不能写成「当一个检查变红时，这个数不许出现在结论里」。** 写不成，它就是一句感慨。

`metric-card.mjs` 会拒掉「无」「暂无」「一般都可」这类值，并要求这一项至少八个字符——因为它是被抄成标题最多的那一项。但它判不了**这个禁令是不是真的对应一个能触发的检查**。

## 问题 5 — 它和谁一起看才有意义？

只在有比值或复合指标时问。这一问防的是上面那个「声量效率」。

**推荐答案先给：把这两个数各自的混淆变量列出来，看它们重不重叠。**

GMV 和提及量都受促销影响：大促同时抬高两者。所以「GMV ÷ 提及量」在促销周会**因为同一个原因**同时变大变小，看起来像稳定的效率，实际是同一个变量在动。

**判据：这个比值变大，可能因为哪几个原因？** 少于两个，这个比值是有信息的；三个以上，它测的是噪音。

这一项没有落进八项字段，它是**层间关系**，记进卡外的「和谁一起看」一节，或者直接决定不做这个指标。

## 问题 6 — 改口径的时候，旧数据怎么办？

**推荐答案：旧数据不重算，新数据带新版本，界面显示版本号。**

改口径有三种原因，动作不同：

| 改什么 | 动作 | 旧数据 |
| --- | --- | --- |
| 加了新的数据源 | 版本 +1，标注从哪周开始含新源 | 不重算 |
| 改了权重或阈值 | 版本 +1，新旧并行跑一个周期对比 | 不重算 |
| 发现算错了 | **版本 +1，且旧版本的数要作废并留档** | 不重算，但要标记作废 |

第三种最容易被悄悄处理：直接重算，看板上数字跳了一下，没人知道为什么。

**为什么旧数据不重算**：重算之后，跨期比较里「口径变了」和「业务变了」分不开——而这是数据产品里最贵的一种错误。留着一个带版本号的不一致，比造一个看不出痕迹的一致要便宜。

**判据：能不能说出上一版是哪一版、差在哪。** 说不出来，等于没有版本。

## 检查器管什么，你管什么

这一层有一个能跑的检查器，它的边界必须说清楚，否则会被当成「填完就对了」。

```bash
node scripts/metric-card.mjs check          # 全部卡
node scripts/metric-card.mjs new "指标名"   # 生成模板
```

| 它**能**判 | 它**判不了** |
| --- | --- |
| 八项都有、都不空 | 定义是否真的可执行（「加权求和」能过） |
| 是不是抄了小标题当内容 | 分子分母是不是同一层 |
| 是不是「无」「暂无」「较高」这类空话 | 已知偏差写的方向对不对 |
| 模板占位符有没有被替换掉 | 禁令是不是对应一个能触发的检查 |
| 口径版本里有没有版本号 | 版本之间的差异有没有记录 |

**实测过一条**：一个把 GMV ÷ 提及量 × 互动率 的指标，八项全填、无空话、版本号规范，检查器全绿。所以这个 skill 的价值不在「帮你填满八项」，在**问题 1 和问题 5**。

## 这个层怎么假装成功

**八项填得很像。** 每项都有内容，专业术语齐全，读起来像一份数据字典。判据：**换一个人能不能算出同一个数**。

**已知偏差写成免责声明。** 「本指标仅供参考」不是偏差。判据：说得出一件具体的事会让它偏。

**禁令写成感慨。** 「数据质量差时请谨慎使用」不是禁令。判据：能不能挂到一个会变红的检查上。

**口径版本当成发布日期。** 填 `2026-10-28` 而不是 `v3`。检查器只要求「里面有个版本号」，
而日期里也有数字，所以它放行——但它说的不是同一件事：日期回答「什么时候」，版本回答
「和上一版差在哪」。写着日期的卡，改过一次之后你无法说出改了什么。

**指标数量当成进展。** 二十个指标没有一个是决策需要的，不如三个。判据回到开场那一问：这个数字错了，哪个决策会错。

## 和 8+3 其他层的接口

指标层的输入是打标层的输出，输出是分析层的输入。两边各有一处不明显的约束：

- **上游（打标）**：读到的 `taxonomy_version` 不等于指标卡声明的版本时，**报警，不许猜**。标签改版后静默合并，会让「去年的数和今年的数不是一个体系」而看不见。
- **下游（分析）**：交给分析层的每个数都要带 `metric_version` 和分母规模。分母骤降时分析要拒绝出结论——那是「数还在但不是那个数」的典型形态。

这两条写在 `docs/product/data-product-layers.md` §三 的契约里，`matrix-check` 会检查它们有没有被填。

## 退出条件

**拿给一个没参与的人，他能算出同一个数，并且说得出这个数什么时候不能用。**

两件都要。算得出但说不出禁令的，是一个会进结论的数字；说不出算法但说得出禁令的，是一个别人的数字。

如果两件都做不到，问题 1 没答完，回去。

## 落盘

```bash
node scripts/metric-card.mjs new "A2+ 正面加权互动量" > work/metrics/A2-plus-positive-weighted.md
# 填完六个问题的答案，然后：
node scripts/metric-card.mjs check
```

卡住 `work/metrics/`，不进 `work/designs/`——设计记录是**一段对话的落盘**，一次四问就完；指标卡是**一个会长期存在的定义**，会被引用、会被改版、会并存多个版本。两者的生命周期不同，所以不同目录。

卡里除了八项，另加两节（不参与检查器校验，但没有它们这张卡不完整）：

```
## 和谁一起看才有意义
（问题 5 的答案。没有比值指标时可以写「不适用：本指标不参与任何比值」。）

## 版本记录
| 版本 | 什么时候 | 改了什么 | 旧数据 |
|---|---|---|---|
| v1 | 2026-10-28 | 初版 | — |
```
