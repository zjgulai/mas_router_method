# 结论层：一句能被推翻的话

**开场先问：「如果这条结论是错的，谁会先发现，怎么发现？」**

答得出来，继续。答不出来——「应该会有人觉得不对」不算——这条结论不该发出去。它会以一个数字的身份活下去，而没有人有能力质疑它。

结论层不是分析的包装。**它是分析层唯一被允许泄漏到产品外面的部分**，所以之前每一层的错误都会在这里变成一句话。

## 这一层最贵的一种错

一条结论卡：

> **主张**：更好的表现
> **依据**：看了很多数据
> **决策含义**：有助于决策

`verify-conclusion.mjs` **全绿**——因为它的证伪条件 `ci-excludes-zero` 在给的数据上成立了。它不检查这张卡该不该存在。我实测过。

三处问题，对应三种最常见的伪装：

- 「更好的表现」**没有数字**。一个不能说错的句子，也不能被检查。
- 「看了很多数据」**没有版本**。三个月后没人能重新导出那个数。
- 「有助于决策」**没有动作**。星期一的哪件事会因为这条结论而不同？

所以这一层的第一条纪律：

> **一条结论必须同时能被执行和被推翻。执行不了是空话，推翻不了是意见。**

`conclusion-card.mjs` 判前一句，`verify-conclusion.mjs` 判后一句。两个都要跑，它们回答的不是同一个问题。

## 六个问题，一张卡

一问一答，答案落进 `work/conclusions/<id>.json`。前两问定「它说的是什么」，后四问定「它凭什么、什么时候不算」。

先给推荐答案，让他同意或纠正。

| 问题 | 卡上的字段 | 什么时候问 |
| --- | --- | --- |
| 1. 它说谁、在什么范围里、多少？ | 主张 + 范围 | 总是 |
| 2. 它有多不确定？ | 区间 | 总是 |
| 3. 它凭什么？ | 依据 | 总是 |
| 4. 什么情况它就不成立了？ | 证伪条件 | 总是 |
| 5. 谁会做什么不一样的事？ | 决策含义 | 总是 |
| 6. 它被推翻过吗？ | status | 每条都问 |

---

## 问题 1 — 它说谁，在什么范围里，多少？

**推荐答案先给：一个句子，里面有一个数、一个对象、一个时间窗。**

三个成分缺一个就变成另一种东西：

| 缺什么 | 变成什么 | 例子 |
| --- | --- | --- |
| 缺数 | 一个印象 | 「更好的表现」 |
| 缺对象 | 一个普适论断 | 「声量带动 GMV」——哪个市场？哪个品类？ |
| 缺时间窗 | 一句无法复核的话 | 「US 弹性是 1.7」——哪 52 周？ |

**时间窗不是形式要求。** 没有它，三个月后你无法回答「这条还成立吗」和「我是不是在看另一段时期」——而这两件事的动作相反：前者要重新估计，后者要重新划范围。

**形容词是这一项最容易漏的漏洞。** 「显著提升」里有一个「显著」，而它可能是统计显著，也可是「我觉得挺明显」。数字会强制你把后者换成前者。

判据：**把这句话念给一个不做这行的人，他能说出「谁、多少、什么时候」吗？**

## 问题 2 — 它有多不确定？

**推荐答案先给：两个数，不是一个。**

一个点估计在语义上等价于「区间是零宽」——这是一个极强的断言，而它几乎总是假的。

**跨过 0 的区间必须标成「无结论」，不是「效应弱」。** 这是整个产品最重要的一条纪律，因为：

- 「弱效应」会被引用进一次预算会
- 「无结论」不会

而这两种说法来自同一个区间 `[-0.004, 0.011]`。区别只在你叫它什么。

**区间跨 0 时，这条结论不该落卡。** 它可以在过程记录里存在，但它不进结论库——因为结论库里的每一条都会被人当作「成立的东西」来读。

判据：**`ci-excludes-zero` 这条证伪条件在这张卡上会不会触发。** 会，就是无结论。

## 问题 3 — 它凭什么？

**推荐答案先给：指标名带版本号 + 一条能走通的路径。**

三样东西，缺一样「依据」就只是一个链接：

| 要素 | 为什么 | 例 |
| --- | --- | --- |
| **指标名 + 版本** | 口径变了数就变了，不说版本等于没说 | `A2+ v2` |
| **数据截面** | 哪个区域、哪段时间、哪个品类 | `US · 2025 W01–W52` |
| **可追溯的产物** | 一条能重新跑出来的命令或记录 | `E-006` |

**「依据」一栏最常见的假货是形容词。** 「基于大量真实数据」——多少条？哪个源？哪个版本？三个问题一个都答不上。

判据：**从这条卡片出发，能不能一路点到原始载荷，中途每一跳都显示它用了哪版标签体系和哪版口径。** 做不到这点，血缘就只是宣称。

## 问题 4 — 什么情况它就不成立了？

**推荐答案先给：一个已注册的条件名，不是一句话。**

这是结论层和「一个 dashboard」之间唯一的分界线，也是设计里唯一一处要求**写成代码**的东西。

`scripts/conclusion-conditions.mjs` 里每个条件是一个纯函数，输入是一小块固定形状的数据，输出是三种判定之一：

| 判定 | 意思 | 该做什么 |
| --- | --- | --- |
| `holds` | 检查过了，成立 | 继续用 |
| `falsified` | 触发了 | **立刻转 superseded**，不是留在看板上 |
| `unmeasurable` | 输入不够，查不了 | **不是通过**——去补数据或改检查 |

**第三种是这一层的陷阱。** 一个没人看过的绿灯，和一个检查通过长得一模一样。`verify-conclusion` 因此给了它独立的退出码（2），而不是混进 0。

**写不出条件名，就是设计阶段那个失败模式的复发**：「如果结论错了」不是条件，因为它无法被触发。这时不要往下写卡，回去看这条结论到底可证伪在哪一步。

判据：**这条条件有没有一个能变红的数据。** 造得出来，它能用；造不出来，它是句子。

**四类结论各自的典型条件**（都在 `conclusion-conditions.mjs` 里）：

| 结论 | 必查的条件 | 它挡的是什么 |
| --- | --- | --- |
| C1 区域弹性排序 | `ci-excludes-zero`、`regional-sign-consistent`、`no-uncontrolled-events` | 区间跨 0；符号在各区域翻转（没有统一机制）；本地大促把效应抢走 |
| C2 滞后结构 | `lag-has-peak`、`sample-adequate` | 曲线单调（效应是同期的，滞后故事不成立）；样本不够 |
| C3 单次事件增量 | `no-uncontrolled-events`、`ci-excludes-zero` | 同期新品上市或平台活动 |
| C4 预算边际回报 | `budget-has-variation` | 一年只调整过一两次，无识别力 |

**`lag-has-peak` 是补上的。** 原来七条条件里没有一条能判 C2——把 C1 的条件套给 C2 会静默通过，因为那些条件对滞后曲线一无所知。这是写 `conclusion-card.mjs` 时拿一张真实 C2 去试才发现的。

## 问题 5 — 谁会做什么不一样的事？

**推荐答案先给：一个动词 + 一个对象 + 一个方向。**

这是六项里最常被写空的一项，也是唯一一项**能反过来判断这条结论该不该存在**的。

四个必须做不同的东西：

| 成分 | 反例 | 正例 |
| --- | --- | --- |
| 动作 | 「有助于决策」 | 「挪」「停」「加」「砍」 |
| 对象 | 「优化投放」 | 「Q3 的社媒预算」「DE 的达人池」 |
| 方向 | 「调整一下」 | 「从 DE 挪 15% 到 US」 |
| 时间 | 「以后」 | 「Q3 之前」 |

**如果答不出「谁会做什么」，这条结论不该写。** 不是因为写得不好，是因为它没有存在理由——它会占掉一个决策者的注意力，而那个注意力本可以给一条能改变行为的结论。

判据：**说完这条之后，星期一的哪件具体事会不同？** 说不出，删掉它。

## 问题 6 — 它被推翻过吗？

**推荐答案先给：`active` 或 `superseded`，没有第三个。**

两个值，一条规则：**被推翻时新增一条 `superseded` 的卡，不改原件。**

「改写原件而不是新增」是这一层最贵的错误，因为：

- 删掉旧结论，就失去了「我们曾经相信过什么、为什么信错了」的记录
- 那份记录是唯一能让下次判断更快的东西
- 而且它是**唯一能让人承认自己判断依据变化的地方**——改掉原件之后，没有人记得当初依据过什么

**被推翻时还必须写「为什么推翻」。** 三句话：旧结论主张什么、什么条件触发了、新结论是什么。缺第三句，等于只留了一个墓碑。

判据：**能不能列出这个产品曾经相信过、后来不信的三条。** 列不出来，说明推翻都被就地改写了。

## 两个检查器，两个问题

**它们是两个问题，不是一个。** 混着跑会得到「全绿」而结论是空话。

```bash
# 这张卡该不该存在？（六项齐不齐、主张能不能错、决策有没有动作）
node scripts/conclusion-card.mjs cards.json

# 这张卡还成立吗？（跑每条证伪条件，报哪条触发了）
node scripts/verify-conclusion.mjs cards.json
```

| `conclusion-card.mjs` 能判 | `verify-conclusion.mjs` 能判 |
| --- | --- |
| 六项有没有缺 | 条件触发了没有 |
| 主张里有没有数字 | （不判主张） |
| 主张里有没有形容词、含糊词 | （不判形容词） |
| 范围里有没有时间窗 | （不判范围） |
| 区间是不是两个数、有没有反 | 区间跨 0（作为一条条件） |
| 依据里有没有版本或可追溯产物 | （不判依据） |
| 证伪条件名有没有注册 | 注册的条件跑出什么 |
| 决策含义里有没有动作动词 | （不判决策） |
| — | **三种判定：成立 / 触发 / 无法判断** |

**两个都判不了的**：这条结论**对不对**。没有检查器能判，只有数据能。

**实测过一条**：主张「更好的表现」、依据「看了很多数据」、决策「有助于决策」、证伪条件 `ci-excludes-zero` 且它成立——`verify-conclusion` 全绿，`conclusion-card` 报八条问题。

## 这一层怎么假装成功

**主张写成一句总结。** 读起来像结论，没有数字。判据：能不能构造一个数据，让这句话变错。

**区间写成点估计。** 「提升 1.7%」而不是「1.2–2.2%」。判据：那两个数是两个吗。

**依据写成来源。** 「来自 ERP」「来自 Apify」说了等于没说。判据：版本号在哪。

**证伪条件写成条件句。** 「如果声量不带动 GMV」——这不是条件，是重述主张。判据：有没有一个已注册的名字。

**决策写成意义。** 「有助于理解市场」。判据：有没有动作动词。

**推翻时改写原件。** 最省事，也最贵。判据：能不能列出曾经相信过、后来不信的三条。

## 和 8+3 其他层的接口

结论层在最末端但也在最中心，它同时受两边约束：

- **上游（分析）**：区间跨 0 的分析结果不许落卡。有效样本不足时降级为描述性——描述性结论也允许存在，但它不能有 `决策含义` 里的动作动词，写法是「我们观察到 X」，不是「应该做 Y」。
- **下游（报告）**：证伪条件必须是**已注册的函数名**。未注册的名字 `verify-conclusion` 判「无法判断」，而那**不是通过**——报告层因此会正确地拒绝按它告警。
- **回环（迭代 → 结论）**：`superseded` 是唯一的推翻路径，走状态迁移，不走改写。这是 `matrix.json` 第五条衔接（分析→结论）与最后一条（报告→迭代）的落点。

## 退出条件

**两个命令都跑过，且都通过：**

```bash
node scripts/conclusion-card.mjs work/conclusions/*.json    # exit 0
node scripts/verify-conclusion.mjs work/conclusions/*.json  # exit 0 或 2
```

`verify-conclusion` 的 exit 2 是**无法判断**——它不是通过。这时要么补数据，要么把那条条件从卡上去掉并说明为什么它不适用。**留着一条查不了的条件，比没有条件更糟**：它让人以为查过了。

再加一条人工判断：**把这张卡给一个会据此行动的人看，他能不能说出他会做什么不同的事。** 说不出，问题 5 没答完。

## 落盘

```
work/conclusions/
  C1-regional-elasticity.json
  C2-lag-structure.json
```

一条结论一个文件，不是一个大 JSON——因为**推翻是新增**，一个文件里塞十条会让每次推翻都是一次全文改写。

形状：

```json
{
  "conclusions": [{
    "id": "C1",
    "claim": "控制促销与缺货后，声量每提升 10%，US 的 GMV 提升 1.7%",
    "scope": "US · 2025 年 52 周 · 母婴个护",
    "interval": [0.012, 0.022],
    "basis": ["A2+ v2", "B1 v1", "E-006"],
    "conditions": ["ci-excludes-zero", "regional-sign-consistent", "no-uncontrolled-events"],
    "decision": "把 Q3 的社媒预算从 DE 挪 15% 到 US",
    "status": "active"
  }]
}
```

`work check` 目前不校验这个目录——**这是已知缺口**，记在 `docs/product/data-product-layers.md` §五。
