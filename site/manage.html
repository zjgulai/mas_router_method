总览 / 管理

管理 横跨七阶段

管理不是第八个阶段，是七阶段的地基。票据在需求时开，状态在开发时流转，证据在验收时落地，事故可能发生在任何一刻。把它抽成"第八步"，前七步就都在没有记录的情况下跑完了。

为什么必须有这个。 这个仓库曾经有一套票据系统——五张票，结构规范，还定义了状态字段。结果是：其中两张票要求的代码早就写完并通过测试， 票上还写着 ready-for-agent。系统没坏，只是没人更新。 管理层的唯一目的，是让"现在的真实状态"不需要任何人记得去维护。

一条铁律

每一类信息只有一个家。可以被多处引用，不能被复制。

复制不会立刻出错。它会先安静地存两份，等改了一个忘了另一个时才出问题。这个仓库已经犯过一次：执行票同时住在 .scratch/ 和 work/tickets/。

判断标准只有一个：它会不会变

会变不会变
特征有状态、会流转、会关闭、会过期写完就不该再动
住哪work/docs/
例子票从 open 走到 done、事故从 open 到 closed、产物会过期ADR 接受后不改、规格是某一版的快照

这条比"按主题分"可靠。按主题分的话，"决策"既像工作又像文档，每次都要重新吵一遍；按"会不会变"分，"ADR 接受后就不该改"是一个明确的事实，不需要判断。

七个寄存器

目录放什么流转ID谁写
work/requirements/需求：一句话承诺drafting → confirmed → droppedR-阶段 1
work/tickets/执行票：跨会话的工作单元open → in-progress → awaiting-verification → doneT-阶段 2–5
work/incidents/事故：计划外发生的事open → contained → closedINC-任何阶段
work/artifacts/有持续成本的东西active → expiredART-阶段 6
work/evidence/证据：命令 + 原始输出无状态，只增不改E-阶段 4
work/receipts/回执：谁收到了什么无状态，只增不改REC-阶段 5
docs/adr/决策记录无状态机，永久保留ADR阶段 2

两个设计决定，都不显然

状态是目录，不是文字

旧票据写 **Status:** ready-for-agent——纯文本，没人校验，所以漂移了。

现在票住在 work/tickets/open/、work/tickets/done/。移动文件就是改状态， 状态无法与文件位置矛盾，ls 就能看全局。

代价：改状态要移动文件，所以有 work-move 命令先校验转移是否合法。

证据是可复跑的命令，不是一句"已完成"

一份证据长这样：一条命令 + 它的原始输出 + 它能证明什么 + 不能证明什么。

最后两段是重点。"通过"这个词太容易写，而"这条测试证明了解析器，不能证明供应商可达"是真话。

票要标 done，work-move 会检查 evidence: 字段；没有就拒绝。

怎么用（不需要记命令）

一个 skill，anb-manage。你说话，它读写目录。

你说它做什么
「现在什么情况？」跑 work status，按它的输出回答，不凭记忆总结成"看起来还行"。
「这张票能关了吗？」查三件：有证据吗、证据证明的是这张票还是别的东西、有没有一条检查真的红过。
「这里有个问题」先分辨是"我们打算做的事"还是"发生在我们身上的事"——前者开票，后者开事故。
「这个东西该放哪？」读 work/LAYOUT.md。它会不会变？会 → work/；不会 → docs/。

两条命令，都可以当 CI 门禁

node scripts/work.mjs check    # 记录本身是否合法：ID 唯一、done 有证据、needs 指向存在
node scripts/layout.mjs        # 文件是否在 LAYOUT.md 说的位置

work check 在一个票标 done 却没有证据时会拒绝。layout check 在一个文件放错目录时会报错。两个都返回非零退出码，能直接当门禁用。

这套东西自己出过三次错，都是同一个形状。

一、work status 里硬编码了 ticket，而 schema 写的是 tickets——五张票全部不可见，报告说"0 张票，一切正常"。
二、schema 解析器的正则只匹配 [A-Za-z0-9_]，带连字符的 in-progress 和 awaiting-verification 被丢掉——票永远到不了 done。
三、check 统计时漏掉了 append-only 寄存器——五张票加三份证据，它报"5 条记录"。

三次都没有抛错，三次都给出了自信的错误输出。每一个都有测试锁住，而测试是通过"临时把 bug 注回去、看它会不会红"来验证的。
