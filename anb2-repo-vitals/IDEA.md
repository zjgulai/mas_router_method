# 阶段 1 产出：想法

按 `anb-idea` 的五句话写。每一句一行，不展开。

---

**谁用**：一个正在为开源项目找「该不该用」答案的开发者。具体到某个人：手上有三个候选库，要在周五前定一个。

**什么时候用**：他刚在别人的 README 里看到这个项目的名字，还没决定要不要花两小时试它。

**为什么现在没有更好的办法**：他去 GitHub 页面自己看，看到的是星数、最后一次提交、一堆 issue 标题。这些数字每一项单独都没有意义——星多可能是营销，issue 多可能是用户多，也可能是质量差。要把它们变成判断，他得自己查几个来源再心算。

**用完他能做什么以前做不到的事**：三十秒内拿到一句结论，并且这句话的每个数字都能点回原处核对。

**什么情况说明不该做**：如果实测下来，五个指标拼出来的结论和资深开发者凭经验扫一眼得出的结论，有超过三成不一致——那说明这些指标不承载判断，只是把「需要经验」这件事包装成了数字。

---

## 这一阶段的验收

**动作**：把上面五句念给一个不做开源的人听，他能说出「所以这是在帮人判断该不该用一个代码库」。

**自检**：我念过一遍。第三句（为什么现在没有更好的办法）太长，一句里塞了两个意思。已拆。

## 一个我差点写错的地方

第一版我写的第五句是「如果没人用」。那是废话——任何产品没人用都不该做，它不构成对这个具体产品的否定条件。

真正能推翻它的是：**这些指标不承载判断**。也就是说，我把「资深开发者的直觉」当成了它要替代的东西，如果替代不了，它就只是把经验包装成数字。这一句才是真正的否定条件，因为它可以在产品做出来之后被测量。

**这件事记下来**：第五句不是「什么会让它失败」，是「什么会证明我关于它为什么值得做的假设是错的」。这两个不一样，前者容易写成风险评估，后者才是可证伪的。
