三个工具的分工一句话说清：模型从哪来（Magpie 本地网关，127.0.0.1:3425，协议互转+路由组容灾）、活怎么派（Lody 多机控制平面，worktree 隔离+异步回执）、昨天学到的怎么带到今天（Nowledge Mem 会话注水+持久记忆）。互不依赖，接起来却是一条完整流水线：记忆注水 → 调度派活 → 路由降本 → 验收回流 → 记忆沉淀。

三个衔接点

每个都很薄，薄到一条命令或一个协议。这正是它们能长期共存的原因。

  • ① 记忆注水：Nowledge Mem 的 hook 独立工作，任何会话（含 Lody 派发的）启动即拿到简报+规则
  • ② 模型导入：lody agent-config import-magpie，Lody 模型选择器里直接出现 magpie/* 全部路由组
  • ③ 经验回写：验收会话里的决策用 nmem m add 写回，下次注水就有了

六步 SOP

以"给 Agent 加一个新工具"为例，每步标谁在场。

  • 1 开工（Mem）：nmem m search 查旧账：做过没有？为什么放弃？
  • 2 想清楚（人）：写 spec，关键决策当场 nmem m add
  • 3 派活（Lody）：session_create 派到远程 worktree，不阻塞
  • 4 选模型（Magpie）：探索用 free 组，正式生成切 opus 组
  • 5 验收（人+Lody）：Diff 行级批注回传；数字对不对跑 eval
  • 6 沉淀（Mem）：合并后蒸馏本线程，教训写回记忆

为什么是这三件

  • Magpie：所有 Agent 请求统一走本地 3425 端口；group/* 路由组遇 429 自动切换，探索用 free 组、正式生成用 opus 组，同一份工作 token 成本差一个数量级
  • Lody：把多台机器池化成一个执行池，每个并行会话独立 worktree 互不污染；长任务返回 operationId 即结束回合，后台跑完自动回执唤醒
  • Nowledge Mem：会话启动自动注入工作记忆简报与 Space 规则；nmem m add 沉淀带类型的决策记忆，写前先检索去重
  • 验收用 Lody Diff 行级批注直接回传给 Agent 当下一轮输入；人只出现在派活和验收两头，中间全是机器
两条红线：开工第 1 步的检索不能省，记忆里的旧决策不查就等于不存在；第 6 步写记忆前先去重，重复记忆会让检索退化，最终整条链失灵。什么时候别用这套：单人单机单任务直接跑 claude；生产环境订阅桥接有 ToS 风险且本机单点，走正规 API + 企业网关。
